# 数据库每日备份

## 执行安排

- Windows 计划任务：`HedeDatabaseBackup`。
- 时间：每天北京时间 **02:00**，服务器时区为 `China Standard Time`。
- 数据库：`commodity_department`，使用项目现有数据库连接配置。
- 目录：`E:\HedeDatabaseBackups\commodity_department\YYYYMMDD`，日期按北京时间计算。
- 保留范围：当天及之前 6 个自然日。只有当天的新备份成功并通过校验后，才删除更早的已验证备份；当天失败时保留原有备份。
- 执行账号：`SYSTEM`，无需登录桌面或启动网站后端。
- 失败重试：每隔 30 分钟，最多 3 次。错过计划时间后在系统可用时补跑，同一天成功后重复触发会跳过导出。
- 同时只允许一个实例；单次最长运行 8 小时。

## 备份文件和校验

| 文件 | 内容 |
| --- | --- |
| `database.dump` | PostgreSQL custom 格式的完整数据库逻辑备份，使用 Zstandard 压缩 |
| `globals.sql` | 数据库角色和表空间定义 |
| `manifest.json` | 数据库名称、业务日期、源库大小、服务器版本、文件大小和 SHA-256 |
| `*.stdout.log`、`*.stderr.log` | 各备份及校验步骤的诊断日志 |

每次依次导出角色及数据库、读取归档目录、完整读取并解压归档生成 SQL 到 `NUL`，然后计算 SHA-256。所有步骤成功后才把临时目录发布为日期目录。

完整读取校验不会连接数据库执行恢复 SQL。它可以检查归档能否完整读取和解压；它不等同于在独立数据库完成恢复演练。恢复演练应另选隔离实例，并验证表结构、记录和关键业务查询。

此任务备份数据库内容；共享盘图片、程序代码、`.env` 和服务器外部文件应另行管理。备份目录仅授予 SYSTEM 和本机管理员访问权限，数据库密码通过子进程环境传入，不写进命令行或日志。

## 空间与清理保护

导出开始前，根据上一份备份大小预留新文件空间，至少保留 15 GiB 可用空间。运行期间每 3 秒检查一次余量；空间不足会停止当前导出，清除本次未完成的大文件并保留已验证备份。

历史清理只处理当前目录下、日期名称正确、数据库归属匹配、具有有效清单且文件大小匹配的备份。未知目录、损坏清单和其他数据库文件不会自动删除。中断后的临时目录只清除有本任务归属标记的未完成数据文件，并保留诊断日志。

容量规划应容纳至少 **8 份压缩备份和 15 GiB 余量**：7 份已保留备份，以及清理前正在生成的新备份。数据库增长后需按实际备份大小复核剩余容量。

## 查看与手动运行

网站的定时任务执行记录中可按 `HedeDatabaseBackup` 查看运行状态。详细日志为 `backend\logs\database_backup.log`。

在有权限的 PowerShell 中手动触发及查看状态：

```powershell
Start-ScheduledTask -TaskName HedeDatabaseBackup
Get-ScheduledTaskInfo -TaskName HedeDatabaseBackup
Get-Content -LiteralPath backend/logs/database_backup.log -Tail 30 -Encoding UTF8
```

任务结果 `0` 表示成功；运行过程中 Windows 可能显示 `267009`（正在运行）。失败时先查看主日志和该临时目录中的步骤日志。

入口为 `backend/scripts/database_backup_daily.cmd`，由原生 PowerShell `backend/scripts/database_backup/run.ps1` 组织执行，私下调用 Python 配置桥 `daily.py` 读取现有连接配置并记录任务状态，再运行 `daily.ps1` 备份。配置桥的标准输出含连接凭据，只能由运行器内部捕获，禁止手动输出或重定向到日志。计划任务配置脚本为 `backend/scripts/configure_database_backup_daily_task.ps1`，注册后保存的任务 XML 位于 `backend/logs/scheduled-task-backups`。
