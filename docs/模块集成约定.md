# 模块集成约定

版本：1.3

更新日期：2026-11-06

配套文件：[模块开发规则与 UI 规范](项目开发规则与UI规范.md)、[模块适配模板](项目规范适配模板.md)、[回归验收清单](通用回归验收清单.md)。四份文件放在同一目录即可转交独立模块开发者。

## 1. 共同目标与完成条件

所有独立开发的页面、流程和模块，完成后都要集成到当前赫德主项目。独立环境用于分工开发和验证，设计时即明确最终代码位置及接入方式；不能等交付时再重写技术栈、UI、登录或数据关联。

默认接入主项目现有前端和后端应用。模块独立运行成功是阶段结果；最终须在主项目隔离集成环境完成路由、菜单、身份权限、数据、迁移及受影响功能的验证。确需单独保留服务的模块，开发前记录原因、接口、身份信任、部署、运维及恢复方式，由主项目维护者核对兼容性。

本说明规定集成要求，不执行集成、迁移或发布，也不规定代码版本管理流程。

## 2. 主项目共同基线

以下按 2026-11-06 本地配置和源码整理，不能据此认定线上部署版本；开始开发和最终集成前都核对主项目实际版本与变化。

| 能力 | 当前基线／相对主项目根目录的入口 | 模块要求 |
|---|---|---|
| 前端 | Next.js 16.1.7 App Router、React 19.2、TypeScript 5.9 严格模式；`frontend/package.json`、锁文件 | 使用相同框架与类型约定，不另起不兼容前端体系 |
| 样式与组件 | Tailwind CSS 4.2、现有 Radix／shadcn 风格组件；`frontend/components/ui/`、`frontend/app/globals.css` | 复用主题、尺寸和组件；不复制第二套同名基础组件 |
| 字体与根布局 | 本地 Geist／Geist Mono 及中文回退；`frontend/app/layout.tsx` | 集成时使用主布局，不带入模块演示壳的根主题、字体加载或重复 Provider |
| 后端与数据 | Python 3.13+、FastAPI、SQLAlchemy 2、PostgreSQL；`backend/pyproject.toml`、锁文件 | 沿用类型、事务、参数化查询和领域规则，新依赖核对兼容性 |
| 前端请求 | `frontend/lib/api.ts`、`types.ts`；浏览器使用 `/api`，`frontend/next.config.mjs` 配置代理 | 请求与类型接入统一封装；开发地址不硬编码到页面 |
| 身份与页面外壳 | `frontend/components/auth/auth-provider.tsx`、`app-shell.tsx`、`frontend/components/sidebar-nav.tsx` | 复用主登录、导航及布局；最终不保留模块独立登录入口和模拟身份 |
| 查询与滚动会话 | `frontend/lib/session-query-state.tsx`、`session-page-state.tsx`、`session-scroll-restoration.tsx` | 按账户及模块页面隔离，遵循主项目刷新与退出清理行为 |
| 服务端授权与路由 | `backend/api/auth_middleware.py`、`backend/api/routes/`、`backend/api/app.py` | 新路由登记权限并注册到现有应用，路由内部校验与菜单权限一致 |
| 身份、角色与数据 | `backend/domain/auth_schema.py`、`backend/storage/auth_repository.py` 及领域／持久化层 | 业务操作者最终关联主用户；共同档案与单据优先引用，不产生第二套正式档案 |
| 数据库迁移 | `backend/alembic/versions/`、领域结构定义及初始化逻辑 | 以集成时主结构为起点增加迁移，不覆盖历史迁移或复制开发库 |
| 默认运行方式 | 前端 3001、后端常用 8137；代理、数据源及构建配置见主项目说明 | 独立开发可用其他端口及隔离目录，集成后使用主项目配置；端口本身不隔离会话 |

以上代码路径是到主项目取得基础时的定位说明，不是要求压缩资料包包含源码。模块适配说明登记实际取得的基础版本、入口和差异；主项目升级后重新核对，不以本表锁死将来的技术版本。

## 3. 开发前填写的接入映射

在适配模板中登记：

| 范围 | 最低需明确的信息 |
|---|---|
| 代码及页面 | 采用的主项目版本、页面 URL、最终目录、业务组件归属、菜单名称与位置 |
| 接口与类型 | 路由前缀、参数／响应、错误和分页方式、客户端方法、服务端注册及鉴权入口 |
| 用户与权限 | 主用户标识、角色及部门含义、复用／新增权限、对象数据范围、敏感字段 |
| 数据与迁移 | 既有对象统一 ID、只读／可写范围、新增流程表、唯一约束、迁移起点与冲突处理 |
| 共同代码与依赖 | 主题、组件、API 与会话来源；新增依赖、主项目文件改动及兼容范围 |
| 开发与交付 | 独立启动、测试账号／数据、模拟适配层；最终移除／保留清单、配置及回退方式 |

未确定的页面或接口内容可以随业务设计细化，但共同技术栈、复用入口及数据身份边界应先明确。模块不涉及的业务标为不适用，不为填写表格虚构新功能。

## 4. 代码、UI 与身份接入

- 页面放入主项目 `frontend/app/<module>/`，业务组件按相应目录组织。独立入口与业务组件分开；集成时由主根布局和 `AppShell` 承载，不重复包裹侧栏、登录 Provider、会话 Provider 或主题。
- 新菜单、页面地址和权限一起登记，核对现有页面标签及固定页签允许范围等路径注册；不能仅复制页面文件就认为入口已接通。
- 复用 `Button`、表单、日期、多选、弹窗、错误提示及全局页面类。需要共享组件扩展时说明影响，保持其他页面的尺寸、焦点、滚动与层级。
- 后端接口纳入现有路由、服务及持久化结构，浏览器请求走统一 `/api` 客户端。开发环境模拟接口须单独标识，最终移除或替换为真实契约。
- 独立测试账户不能凭相同数字 ID 自动变成主用户；如有需保留的业务记录，先完成用户及业务 ID 的可信映射，不搬运测试角色、密码、会话或管理权限。
- 权限使用明确动作及数据范围；涉及财务部时沿用主项目已确认的“系统管理之外全部业务权限”边界，系统管理入口继续受限，不为模块接入授予 `*`。

## 5. 数据与迁移接入

- 商品、供应商、仓库、颜色尺码、采购及其他已有记录引用主项目稳定标识。独立开发库可以使用合成档案，不能将它们直接整库导入作为正式资料。
- 接入商品及采购时核对商品身份 `product_identity_id`、品牌范围和既有单据／明细 ID；历史名称字段按主项目已核对的映射处理，不以同名或同货号直接合并。
- 新表只承载模块负责的新增业务，使用模块语义名称与明确约束。统计复用主项目有效状态、业务日期、删除与品牌规则，主单合计及必要历史保持事务一致。
- 迁移需在集成时核对实际结构及迁移头，处理同编号、对象名、索引、约束、触发器及初始化冲突；不直接覆盖 `schema.sql`、已有表或迁移文件。
- 需保留独立环境的真实业务数据时，另提供预览、ID 映射、去重、迁移数量、对账及回退说明。开发测试样本默认不迁入正式环境。
- 现有商品缺失提示、条码解析、库存完成状态及补价等口径见主项目适配说明；不因模块独立开发而重新简化业务规则。

## 6. 集成交付资料与顺序

1. 交付模块适配说明、业务入口与代码清单；列出新增／修改的共同文件、依赖、配置、数据库对象及开发专用文件。
2. 核对主项目最新代码和结构差异，在隔离环境将页面、组件、接口、类型、导航、权限和迁移接到目标位置，移除独立演示外壳及测试绕过。
3. 验证数据库初始化／升级、模块完整业务路径和受影响的已有功能；运行主项目适用的类型、定向测试及必要构建，记录失败与未覆盖部分。
4. 按下表记录集成结果、剩余问题、配置与数据处理、生效步骤及回退条件。验证通过后由负责人员按既定方式发布，业务后端仍由负责人手动启停。

| 检查项 | 通过条件 |
|---|---|
| 主项目运行与依赖 | 模块可在主项目实际依赖和构建中运行，无依赖或根配置冲突 |
| 导航与会话 | 入口、菜单、页签、返回与刷新符合主项目约定，页面无重复布局／Provider |
| 身份与权限 | 主账号可用；未登录、无权、跨范围、导出及敏感字段校验有效，无测试身份绕过 |
| UI 一致性 | 主题、字体、按钮、表格、弹窗、深浅色及窄屏行为与主项目一致 |
| 数据与迁移 | 主档案及业务关联正确，迁移可执行，主表和历史数据无非预期覆盖，测试数据未混入 |
| 业务与回归 | 模块端到端及受影响已有业务通过，统计和导入导出不改变既有口径 |
| 文件与运维 | 开发壳、模拟数据和凭据不作正式依赖；配置、资源、调度及回退说明齐全；不上传 `backend/tests/` 或本地临时产物 |

回归清单中的 GEN-13 必须记录实际主项目集成结果；独立环境的运行结果不能替代它。主项目可访问的长期场景保留，后端本地验证文件仍按原约束处理。

## 7. 维护与资料边界

本文和其余三份配套文件构成可转交的最小资料包；所有相对文档链接限于这四份文件。赫德完整业务适配说明和原业务验收清单由主项目维护，开发者按模块实际涉及内容取得对应章节。

本约定使模块从开发开始按最终集成目标设计，具体页面方案、完整业务字段、实际集成日期及正式发布仍由相应任务确定。
