# 模块开发规则与 UI 规范

版本：1.3

更新日期：2026-11-06

适用范围：分开开发、完成后统一集成到赫德主项目的业务页面、流程及功能模块。

本文规定开发质量、数据、权限及交互的共同要求。独立项目是开发期间的工作边界，交付目标是接入同一个主项目；从开发开始沿用主项目技术栈、组件、身份权限及数据约定。模块特有业务和开发环境通过适配说明登记，不另行决定一套与主项目不兼容的基础。

## 1. 采用方式与规则边界

### 1.1 独立开发模块如何使用

1. 将本文、[模块集成约定](模块集成约定.md)、[项目规范适配模板](项目规范适配模板.md)和[通用回归验收清单](通用回归验收清单.md)放入模块文档目录，先核对主项目基线及实际代码入口。
2. 复制适配模板，另存为模块适配说明，填写负责人、采用的主项目代码版本、最终代码位置、数据与权限映射、开发启动及集成验证入口。
3. 在模块 README 链接上述规范、填写后的适配说明和验收清单；保留原始空白模板，方便其他模块使用。
4. 先检查现有能力和差异，区分“已实现、待实现、不适用”。开发验证与主项目集成验证分开记录；模块单独可运行不等于已完成交付。

主项目的详细约定保存在《赫德项目规范适配说明》中。独立开发阶段至少采用模块集成约定中的共同基线；涉及商品、采购、库存、财务权限等既有业务时，补读主项目对应说明及业务验收清单，不能因分开开发而另设口径。

### 1.2 约束级别与优先级

| 标识 | 含义 |
|---|---|
| 必须 | 适用范围内的新增功能及相关修改应满足 |
| 建议 | 默认方案，可根据项目情况调整并记录原因 |
| 现状 | 已核对的实现，需要注明适用版本或配置 |
| 待实现 | 开发目标，不能表述为已有能力 |
| 不适用 | 目标项目无对应场景，说明依据 |

最新确认的业务需求优先；模块适配说明明确本模块的实现方式及接入位置。与主项目不同的地方记录条款、原因、兼容方式、影响、负责人和验证方式，在开发前明确处理方案，不以旧文档覆盖新需求。

纯前端、只读或不含导入、后台任务的模块可将相关业务能力标为不适用；最终技术、UI、身份、数据及部署兼容要求仍须满足。本规范不包含代码版本管理流程。

### 1.3 开发与维护边界

- 保留他人的现有修改，控制改动范围，不夹带无关重构、格式化或依赖升级。
- 文档、样例及日志不得含真实密码、连接串、Cookie、令牌、私钥或完整敏感业务数据。
- 启停服务、部署、迁移及数据维护按目标项目既定授权和操作职责执行；采用规范本身不触发这些操作。
- 团队可取得的代码、说明和验证资料应有稳定入口，不依赖个人桌面路径或临时目录。

### 1.4 最终集成目标

各独立模块完成后必须集成到当前赫德主项目，统一进入主项目页面导航、登录会话、服务端权限、业务数据及发布流程。开发环境可独立使用端口、测试身份和数据库，最终交付不能依赖只存在于独立环境的页面外壳、账号库或重复正式档案。

默认将业务页面和接口纳入主项目现有应用结构；确需额外运行进程或不同技术时，在模块适配说明记录必要性、契约、维护及部署方式，不能等开发完成后才决定如何接入。实际集成方案与验收按[模块集成约定](模块集成约定.md)执行；本次文档调整不执行代码集成或发布。

## 2. 技术、分层与环境

### 2.1 技术基线与主项目保持兼容

记录采用的主项目代码版本，以及运行时、框架、语言、数据库、包管理器、组件及验证工具的版本依据和维护位置。优先使用主项目配置及锁文件，安装与升级分开处理。

主项目当前采用 Next.js／React／TypeScript、Tailwind 与现有基础组件，后端为 Python／FastAPI／SQLAlchemy／PostgreSQL；具体版本及入口见模块集成约定，以集成时主项目实际依赖为准。模块沿用相同体系，新增依赖先核对兼容性；在适配说明登记类型检查、构建、迁移和启动命令，不为单个模块独立升级主项目核心依赖。

### 2.2 按职责组织代码

| 职责 | 应负责的内容 |
|---|---|
| 页面与视图 | 路由、布局、页面组合及展示 |
| 业务组件／功能模块 | 表单、筛选、详情及模块交互 |
| 基础组件与主题 | 按钮、输入、弹窗、表格、颜色和尺寸变量 |
| 请求及契约 | 客户端请求、数据类型、统一错误处理 |
| 接口层 | 身份、参数校验、授权、响应及流程编排 |
| 领域层 | 业务状态、计算、匹配及业务不变量 |
| 持久化层 | 查询、事务、分页、汇总及批量写入 |
| 任务与维护 | 后台任务、调度、受控补录和诊断 |
| 验证与文档 | 长期用例、合成样本、配置与交付说明 |

实际目录及最终主项目接入位置在适配说明映射。前端不直接访问数据库，查询和写入不散落在视图中；共享逻辑放在明确的负责层，不强制新建空目录。独立运行所需外壳与业务模块分开，避免集成时重复引入根布局、身份 Provider 或应用启动入口。

### 2.3 基础组件与共同代码复用

登记采用的主项目组件、主题、请求、身份和会话封装的代码版本、取得方式及维护者。已有基础优先复用，不因另开项目重复实现相同能力。

同步时一并检查依赖、字体资源、主题变量、导入别名、浮层层级、类型和验证配置。保留本地定制及差异说明，防止直接覆盖；共享包或基础模板只有实际存在且可取得时才列为入口。

基础代码更新说明影响范围和兼容性，目标项目维护者评估后同步，记录采用版本及验证结果。

### 2.4 环境、配置与启动

- 配置项记录名称、用途、默认值、是否必填、读取时机及优先级；样例只含占位值。
- 新开发者应能按说明完成依赖安装、环境配置、隔离数据初始化、测试账号准备及启动核验；命令注明工作目录和操作系统。
- 端口、后端地址、上传、导出、日志及构建目录按项目配置；并行项目避免占用或覆盖同一资源。
- 区分开发、测试和正式环境，核对实际生效的连接和路径；不要只凭配置文件名称认定隔离。
- 应用启动如会初始化表、角色、触发器或执行其他写入，必须注明，不能把启动当作只读检查。
- 同一主机不同端口不隔离 Cookie；独立应用按实际架构采用独立域名、Cookie 或浏览器会话方案并验证。
- 配置是在构建时、进程启动时还是请求时读取，必须说明；修改文件不等于运行环境已经生效。

## 3. 代码、接口与身份权限

### 3.1 命名、格式与类型

遵循目标语言及项目已有命名方式；数据库、外部接口字段与页面内部命名的转换有统一入口。配置格式工具及类型检查，避免无关整文件改写。

请求、响应、表单及状态有明确结构；外部输入先校验再使用，不通过宽泛类型或隐式转换绕过检查。金额、标识、日期、空值等不能仅靠 UI 约定保证正确。

### 3.2 字段与业务范围扩展

新增或变更字段检查完整链路：

来源 → 规范化 → 持久化 → 接口 → 类型 → 表单／详情／列表 → 查询／统计／导出

统一字段中文名、分组、空值和精度；需要追踪来源的导入记录保留文件、工作表、行号或等效来源信息。

品牌、租户、组织等业务范围由可信配置与服务端上下文确定，同编码跨范围存在时隔离读写。汇总范围不能当作单条数据的所属范围写入；不得任意截码或跨范围借值。

### 3.3 API 与授权

- 请求复用统一客户端封装，正确处理登录凭据、超时、取消及服务端业务错误。
- 服务端校验身份、权限及对象的数据范围；页面隐藏按钮不能代替接口授权。
- 查看、编辑、导入、导出、敏感字段和系统管理分别评估权限，按项目登记的矩阵执行。
- 当前操作者取自可信身份上下文，不相信表单传入的账户名、角色或用户 ID。
- 参数错误、非法日期、超限数值及未知状态在写入前拒绝，错误说明业务原因及可执行的下一步。
- 契约变更联动调用方、类型、分页、空值及验证；说明兼容方式。
- 操作日志记录操作者、动作、目标和必要变化，不记录凭据。审计是否属于成功事务的必要条件须明确；非关键日志失败不能把已成功操作误报为未完成。

### 3.4 用户与跨系统身份

使用稳定用户标识；姓名只用于显示，不能凭同名判断是同一人。跨独立数据源采用“来源系统＋来源用户 ID”等可信映射，不假定相同数字 ID 即同一人。

沿用主项目权限编码并保持含义一致；新增编码登记模块、动作及数据范围，并纳入主项目角色与部门矩阵。不得在独立模块中另定义同名角色或权限的含义，也不能通过提升到超级管理员解决接入问题。

测试身份只在指定环境有效，不随模块进入正式环境。最终使用主项目登录及服务端身份上下文；独立阶段的身份映射、临时会话与正式接入方式须登记，集成时移除测试绕过，不因复用了前端身份组件就宣称已经接通。

### 3.5 状态更新、重复请求与并发

- 服务端根据当前持久化状态、权限及前置条件校验迁移；具体节点由项目业务设计确定。
- 记录稳定操作者、关联业务对象、前后状态、实际业务时间、系统记录时间及必要原因；时间字段及时区明确。
- 业务变化与必要历史在定义的事务内一起成功或回滚；跨服务／数据库须说明失败恢复方式，不能假定天然原子提交。
- 关键创建和状态推进定义幂等范围、业务唯一约束及不同请求内容的冲突处理；禁用按钮不能代替服务端去重。
- 使用版本条件更新或适用的事务锁检测并发冲突；过期修改明确提示并保留草稿，不能静默覆盖。精度不足的更新时间不作为可靠版本号。

## 4. 数据、统计与前端状态

### 4.1 来源与读写边界

每类业务对象登记权威来源、稳定标识、负责方、可读／可写范围及受控入口。已有档案优先引用；缺项由业务负责方核实后维护，避免出现多套同义正式数据。

已有业务数据优先经受控接口或共同服务访问；后端直连数据库时限定表、字段和权限，保留必要校验、事务及审计。新流程写入自己负责的记录，涉及外部记录时明确同步、幂等及恢复边界。

### 4.2 数值、日期与统计

- 区分未知、空字符串及真实零值；未知显示“—”，真实零显示 0，不用真假值判断隐藏合法零值。
- 编码、单号及条码按标识处理，保留前导零；金额及精确数量使用适合的十进制定点方案，明确精度、舍入、范围和单位。
- 主记录合计基于真实明细计算，增删改及重新导入后同步更新，不接受客户端合计作为唯一依据。
- 每个统计定义数据源、时间字段、业务范围、有效状态、删除规则、单位、分组及边界日期。
- 列表、总数、卡片、流水及导出复用一致筛选口径；同一响应需要一致性时使用同一查询结果或定义清楚的数据快照。
- 区分全量合计与当前页小计；空页、无本期记录或超出页码不能丢失按业务应保留的结转值。
- 库存、财务、订单等具体公式由模块登记并验证；涉及主项目已有数据时复用既有单据类型、状态、例外及补价规则，不能维护第二套相互冲突的统计口径。

### 4.3 查询、选择与会话

- 区分正在编辑的筛选条件和已提交条件；结果、分页、合计、导出及跨页选择使用同一份已提交条件。
- 同字段多选默认匹配任意选中项，不同字段默认同时满足；不同语义在界面说明。
- 请求取消或版本判断防止迟到响应覆盖新数据；互不依赖的请求可并行，避免重复请求和不稳定依赖。
- 跨页选择明确采用 ID 快照或动态范围，变更筛选后清除不适用选择；不靠逐页抓取冒充全选。
- 查询及滚动状态按账户和页面隔离；跳转、刷新、关闭标签页及退出登录的行为由项目明确并验证。
- 不长期存储未保存业务记录、敏感结果或凭据；没有需要时不引入额外本地缓存。

### 4.4 详情、缓存与错误

实时数据与可缓存数据分别定义缓存键、有效期、更新后的失效和主动刷新方式，不要求所有页面一律禁用缓存。

打开详情读取最新记录，或在更新后明确失效相关列表与详情；失败时提示，不能把列表旧对象无说明地当作最新详情。网络失败、无权限、无匹配和无数据分别表达。

## 5. 导入、导出与后台任务

本章适用于项目实际提供的相关能力。

### 5.1 导入校验

文件类型、实际格式、模板、日期、数值、必填和关联档案在业务写入前校验；扩展名正确不代表文件内部结构有效。

预检查与正式导入复用关键规则，正式写入时重新校验必要前提。缺项列出可处理的编码、行号或原因，并指向项目明确的维护负责方，不固定要求某个部门。

明确整批或分段提交策略、失败影响及覆盖／新增／跳过规则；不得靠放松匹配、静默建档或隐式补值绕过错误。

### 5.2 大文件及内存

项目分别定义上传大小、解析行数、查询参数、写入批量及执行资源上限；这些数值以本项目实现为准。

检查上传、解压、解析、候选展开、校验、写入及结果汇总的完整内存峰值。分批写入不等于分批提交，也不证明解析全程只占一批内存。

大文件验证使用隔离环境和代表性合成数据，观察内存、耗时、查询数和失败回滚；说明未覆盖的规模。

### 5.3 后台任务

定义任务 ID、归属、状态、结果核验、重复请求处理及失败恢复。常见状态可为 queued、running、succeeded、failed，其他状态按实际能力登记。

断网或超时只表示结果待确认，先核验原任务，不自动重新创建。取消、重启恢复和断点续传只有实际支持时才承诺。

定时任务登记时区、实际计划、业务日期、来源、目标、互斥、重试、同日幂等及历史保留范围；修改计划不应顺带重复导入。

### 5.4 导出

明确当前筛选、当前页、勾选或全量范围；使用已提交的查询和相同数据／字段权限，保护敏感字段。

文件名、表头、工作表名、文本编码及数值格式适配实际格式限制，编码保留前导零；不导出已删除、排除或无权数据。缺失资料不从其他业务范围补造。

## 6. 查询性能、数据库与运维

1. 筛选、聚合、计数及分页尽量在数据层完成，避免全量加载后计算和逐行查询。
2. 返回页面所需字段；复用聚合及批量查询，在代表性数据量下核对正确性、延迟和资源消耗。
3. 参数化查询；动态对象名来自可信配置或白名单。
4. 诊断先限定业务范围、时间和数量，使用适用的只读权限、超时和资源限制。
5. 结构变更提供适用版本、迁移顺序和回退条件，协调共同表及调用方；结构快照不能直接覆盖已有业务库。
6. 维护脚本说明预览、目标、幂等、数量及结果；生产修复依据与影响范围可核对。
7. 开发和测试隔离正式数据；清表、重建及测试临时目录清理必须限定在专用范围。
8. 验证性能时不能减少业务必要的状态、范围或删除过滤；报错也不能伪造成零值以换取响应速度。

## 7. UI 视觉基线

本章提供紧凑业务界面基线。模块复用主项目现有主题、字体、布局和组件，在适配说明登记实际映射；下列建议值不能覆盖主项目组件的实际取值。新增业务视觉在既有语义变量内扩展，不另设一套根主题。

### 7.1 颜色、主题与字体

使用语义设计变量表达背景、文字、面板、主动作、次级背景、辅助文字、边框、危险和焦点。业务页面引用变量，不散写与主题无关的黑白或品牌色。

| 语义 | 用途 |
|---|---|
| background／foreground | 页面及主要文字 |
| surface | 卡片、表单和弹窗 |
| primary／on-primary | 主按钮及其文字 |
| muted／muted-foreground | 次级区域及辅助说明 |
| border／focus | 边界及可见焦点 |
| success／warning／danger | 成功、待处理及错误 |

浅色和深色主题分别核对对比度；仅提供一种主题时说明适用范围。不仅靠红绿等颜色表达状态，同时显示文字或图标。

正文采用项目统一字体及中文回退；字体资源与加载方式有明确来源。数值使用等宽数字，编码可用等宽字体，长中文说明保持易读。

### 7.2 布局、间距与尺寸

| 项目 | 建议基线 |
|---|---|
| 信息顺序 | 标题与主要动作 → 查询 → 汇总与结果说明 → 列表／表格 → 分页 |
| 页面内边距 | 小屏 12–16px，桌面 20–24px |
| 间距 | 以 4px 为基准；行内 4–8px，表单 8–12px，区域 16–24px |
| 字号 | 正文／表格 14px，辅助 12px，标题与统计 20–24px |
| 内容宽度 | 普通内容约 1152px，宽表格约 1600px；按业务与视口调整 |
| 按钮高度 | 紧凑 24／28px，默认 32px，大号 36px；输入框建议 36px |
| 圆角 | 字段／按钮约 6–8px，大面板约 12–16px |
| 弹窗高度 | 通常不超过视口 88%–92%，正文内部滚动 |

这些是设计建议，不表示目标组件库已具备对应尺寸或类名；将实际尺寸登记到组件规范。触屏操作建议至少 44px 点击区域，不仅靠放大图标。

避免为截图堆固定偏移。宽表格内部滚动，筛选与按钮可换行，小屏上的查询、关闭及分页保持可达。

## 8. UI 组件与交互

### 8.1 基础组件与按钮

复用项目的按钮、输入、选择、日期、表格和弹窗组件，登记对应入口，不直接依赖其他项目的组件名称或路径。

区分主动作、普通次要动作、行内动作、危险操作及链接。同区域主要动作层级清楚；查询、清空、新增、导入、导出、保存、取消等同类名称一致。

图标按钮有可访问名称；提交中显示状态并防重复点击，后台任务提供核验入口。删除确认说明对象、数量及选择范围。

### 8.2 表单、筛选与日期

- 可见标签与字段关联，placeholder 不代替名称；必填、校验及错误靠近字段。
- 只读、禁用和无权限分别说明；保存失败保留输入，成功刷新受影响数据。
- 选项来自对应业务范围的真实数据或可信字典，按场景支持搜索、多选及合理分页，不用超长列表阻塞操作。
- 下拉限高、避让边缘并处理浮层层级；方向键、回车、Esc、Tab 可用，中文组词不触发提交。
- 多行输入说明分隔方式，区分回车查询与换行。
- 日期控件的业务约束逐项确定，不给所有字段统一禁止未来日期。

### 8.3 表格、分页与选择

文本左对齐、数量金额右对齐，精度一致；使用语义表格、明确表头及可访问排序状态。

固定表头和关键列有背景及正确交叉层级；长文本可截断但提供完整查看，关键编号可识别。

分页说明总数、当前范围及每页条数，重新查询回到合适页码；选择范围与分页分开管理，动态筛选真正传入查询并影响合计和导出。

### 8.4 弹窗、详情与流程

复用统一弹窗，标题及操作可见，正文滚动，避免整页与弹窗多重滚动。层级在项目统一登记，不逐页无限增大 z-index。

打开时焦点进入，Tab 在弹窗内循环，关闭后恢复焦点；Esc、遮罩关闭及未保存内容的行为明确。

详情区分真实缺失、无权显示和未加载；流程状态、负责人、业务时间及动作与服务端一致。并发冲突保留草稿并提供刷新比对。

### 8.5 状态反馈与业务文案

| 状态 | 界面必须说明 |
|---|---|
| 初次加载 | 正在加载，避免闪现无数据 |
| 重新查询 | 显示加载；旧汇总隐藏或明确标为旧结果 |
| 成功且无数据 | 具体空态及可调整条件 |
| 请求失败 | 业务原因和可执行的重试／处理方式 |
| 后台处理 | 任务标识、状态及继续核验方式 |
| 操作成功 | 必要结果及受影响数据刷新 |

文案使用项目规定的产品语言，直接说明问题、影响及下一步。不要将 SQL、堆栈、内部表名作为普通用户处理说明。

批量错误按标题、影响、编码／行号及处理建议组织，长列表限高滚动。只有部分错误返回时标明已显示数量；复制操作有反馈，不声称复制了未取得的全量内容。

### 8.6 响应式与可访问性

验证代表性小屏、平板、桌面和业务常用宽度，可使用 375、768、1280px 作为起点；不只验证单张截图。

所有操作键盘可达并有可见焦点；普通文字按 WCAG AA 4.5:1 检查，大字及必要非文本元素按适用标准检查。错误与状态使用适当的辅助技术提示。

图片有替代文本、尺寸和失败占位；动画简短并遵循减少动态效果偏好，不妨碍业务阅读。

## 9. 验证、评审与交付

### 9.1 按改动选择验证

使用随本文提供的[通用回归验收清单](通用回归验收清单.md)，补入目标项目实际接口、数据和预期。

验证可观察行为及业务不变量，覆盖权限、空值、日期边界、错误、重复提交、并发与统计一致性等实际风险，不只断言内部调用。

类型检查、静态检查、定向测试及必要构建的真实命令放在适配说明；未运行与不适用分别记录。纯文档修改只检查链接、术语、结构及示例，不为低风险文字变更运行全量业务测试。

### 9.2 长期用例与临时产物

长期用例、合成样本和运行说明保存在团队可取得的项目入口；本地临时验证、诊断、导出及测试数据库放入指定临时目录，不冒充共享用例。

开发期间的测试目录在模块适配说明登记；集成与交付遵循主项目限制，当前不得上传或夹带主项目的 `backend/tests/`。长期回归须提供团队可复现的场景、输入规则、步骤和预期，并如实说明自动化入口缺口。

测试仅使用隔离数据；重建表、清理目录及数据库集成验证前核对目标，禁止触达正式数据。

### 9.3 交付记录与生效

交付说明包含问题、最终行为、代码／规范版本、验证结果、已知限制、迁移及生效方式。抽样不等于全库验证，本地修改不等于正式部署。

核对交付文件，排除凭据、日志、导出业务文件、临时数据库和项目明确禁止共享的内容。

发布、迁移和重启按项目职责执行，说明配置和构建的生效时机、执行顺序及回退条件；没有相关变更时不额外执行服务操作。

### 9.4 主项目集成验收

交付时提供新增／修改文件、目标代码位置、路由与菜单、权限、数据关联、迁移、依赖、配置及验证清单。先在隔离环境按主项目实际结构完成集成，验证模块功能及受影响的已有功能；不能只提交独立演示页面或本地运行截图。

集成后验证主项目已有登录与角色、页面导航与会话、UI 主题、数据统计、导入导出及后台任务中实际受影响的部分。迁移从当时主项目的结构继续演进，不直接覆盖主表或导入开发数据库；测试账号、模拟数据及独立启动外壳不成为正式依赖。具体检查项见模块集成约定和通用验收场景 GEN-13。
