# 订单历史归档机制

## 归档范围

以下三张业务表统一采用 PostgreSQL 按年分区归档：

| 逻辑表 | 分区日期 | 日常更新方式 |
| --- | --- | --- |
| `jst_monthly_orders` | `order_time_at` | 按源文件订单日期窗口替换 |
| `jst_aftersale_returns` | `COALESCE(申请日期, 订单日期, 订单时间)` | 按申请日期优先的业务日期窗口替换 |
| `dewu_orders` | `order_date` | 按品牌及源文件订单日期窗口替换 |

售后表分区业务日期的取值顺序为：申请日期、订单日期、订单时间。
`v_jst_aftersale_returns_normalized.business_date` 继续按该规则对外提供。

## 保留策略

- 原逻辑表名保持不变，页面、接口和既有 SQL 无需改表名。
- 历史年度数据保留在 `{表名}_{年份}` 分区，不自动删除。
- 当前年度为热数据，过往年度为只读历史归档数据。
- 每次滚动导入只删除并重写源文件覆盖的日期窗口，不会覆盖窗口外历史。
- 每次导入自动确保数据所属年度、当前年度和下一年度分区存在。
- `default` 分区仅承接空日期或异常日期，避免导入因日期边界中断。
- 售后表直接按日期优先级表达式分区，旧脚本或手工插入无需额外填写字段，
  也会进入正确年度。

## 数据校验

迁移在同一数据库事务中完成，并校验迁移前后的总行数和各年度行数。
任一校验不一致时事务整体回滚，原表继续可用。迁移完成后应继续检查：

```sql
SELECT tableoid::regclass AS partition_name, COUNT(*)
FROM jst_aftersale_returns
GROUP BY 1
ORDER BY 1;

SELECT tableoid::regclass AS partition_name, COUNT(*)
FROM dewu_orders
GROUP BY 1
ORDER BY 1;
```

## 运维方式

手工执行迁移：

```powershell
cd E:\hede\backend
uv run python -m scripts.archive_order_history_tables
```

日常无需手工建分区。若需将旧年度迁移到独立磁盘或对象存储，应先做恢复
演练，再增加冷存储流程；当前机制不会自动移动或删除任何历史数据。
