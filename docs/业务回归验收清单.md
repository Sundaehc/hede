# 赫德业务回归验收清单

版本：1.0

更新日期：2026-11-06

适用说明：[赫德项目规范适配说明](赫德项目规范适配说明.md)，采用[模块开发规则与 UI 规范 v1.3](项目开发规则与UI规范.md)。

本清单包含赫德商品、库存、财务权限及测试入口。独立模块采用[通用回归验收清单](通用回归验收清单.md)并补齐主项目集成场景 GEN-13；涉及既有业务时同时复验本清单受影响场景。下文“规范第 X 节”均指赫德适配说明中的对应章节。

本清单是随仓库提供的长期业务场景入口，不代表下列场景已在当前部署全部通过。修改涉及的模块时选择对应场景复验；独立项目按实际接入范围采用，尚未实现的能力标为“未实现”或“不适用”并说明依据。

## 使用方式

1. 取得目标项目代码，记录代码版本、规范版本、执行人、环境和受影响场景 ID。安装、环境配置及人工启动方式见规范第 2.4 节。
2. 仅在隔离数据库和专用测试账号中执行。构造合成数据，不复制正式密码、用户资料、成本、订单或桌面文件；后台任务和文件来源使用本地测试目录。
3. 按下表准备最小数据、执行操作并对照预期。合成货号、账号和单据可替换，但须保留品牌、状态、空值及边界关系。
4. 在开发任务或交付记录中保存本次使用的合成输入规则、请求步骤或操作步骤及预期，供其他人重新构造；结果分别记为“通过／失败／未执行／不适用”，说明原因。新缺陷补充场景，不把一次运行结果永久写成能力保证。
5. 临时后端脚本、日志、导出及数据库留在忽略目录；不上传 `backend/tests/`。长期复验按本清单执行，不要求其他同事取得本机 `outputs/logs/`。

| REG-03 经手人与重复导入 | 模板一组经手人留空，另一组写入合成姓名；分别走普通／后台导入。用同一任务 ID、文件及参数重复提交；另用新 ID 重复导入相同业务单据 | 空白经手人取当前账户姓名，无姓名回退用户名；已填姓名保留；同任务不重复执行；新 ID 仍执行现有业务冲突检查，不凭新 ID 自动生成重复单据 |

| REG-06 调拨展示及筛选 | 一张 A→B 调拨、一张普通单据仓库为 A、一张普通单据供应商名为 A 但仓库为 C；分别按 A、B 查询并导出混合类型及单一类型结果 | 调拨独立显示出货／入货仓库，筛选匹配两端；不误匹配普通供应商同名；列表、合计、分页和导出同范围；单一单据类型仍按业务生成动态表头 |
| REG-07 多选、跨页与请求先后 | 准备至少两页、不同品牌／年份／季节／品名的数据。编辑条件但不提交，随后多选并查询、换页、全选筛选结果及导出；清空后重查。模拟旧请求晚于新请求返回 | 未提交条件不影响当前结果；同字段多选为任意命中，不同字段同时满足；合计和导出覆盖已提交范围；清空清除不适用勾选；迟到响应不覆盖新结果 |
| REG-08 业务与系统权限 | 准备财务普通账号、无相应业务权限账号及未登录会话；分别通过页面和直接 API 尝试读取／编辑／导出。财务账号另尝试用户管理、定时任务、MCP 令牌及用户管理日志 | 财务可用规范约定的全部业务功能，成本和导出按明确权限；系统管理继续拒绝；无权和未登录不能靠直接请求绕过；不通过增加 `*` 或升级超级管理员取得业务访问 |
| REG-09 详情、会话及错误 | 查询后跳转返回、浏览器刷新、退出并切换账号；列表加载后更新商品再开详情；模拟加载、无数据、请求失败及旧详情响应迟到 | 跳转恢复条件和滚动，刷新恢复默认，账户状态隔离；失败不伪装成空数据／零值；详情不冒充最新。当前商品详情刷新差异见规范第 4.3 节，未改造前如实记录，不忽略失败 |
| REG-10 大文件及后台结果 | 使用合成数据生成足以覆盖多个查询／写入批次的模板；观察整条解析和写入链路的内存与耗时。覆盖上传超限、业务校验失败、网络中断后核验同批次 | 超限按当前上限拒绝；批内失败无部分业务写入；网络中断显示待核验，不自动重传；任务结果可按原批次核对；分批写入不作为内存恒定的证据，不用正式大文件做压力验证 |
| REG-11 新流程状态与并发 | 对新增流程用有权／无权身份请求允许和不允许的状态迁移；同幂等键重复提交及改变请求内容；两个会话基于同一旧版本修改 | 服务端校验权限和前置状态；重复操作不重复生成记录，不同内容明确冲突；第二个旧版本不静默覆盖；状态与业务数据及必要历史同事务；记录操作者、业务／系统时间及必要原因。本场景为新流程验收要求，不宣称中台全部已有 |
| REG-12 并行项目与 UI | 中台与独立项目使用各自端口、数据库、文件目录及隔离会话。检查深浅主题、375／768／1280px、键盘操作、长文本、下拉／弹窗、导入错误提示及复制反馈 | API 指向预期环境，互不覆盖资料或登录态；复用统一主题／组件；动作可达、焦点清楚、无浮层裁切；无匹配／无权／失败分别说明。错误编码只有部分返回时标明已显示数量，不称复制了全量 |

| REG-23 采购单大文件后台导入 | 构造超过 10,000 条明细和超过 1,000 张采购单，覆盖空仓库、跨品牌、不同日期、历史成本、档案别名和尺码；依次预检查、确认、覆盖、新建、取消。模拟第二批写入失败、任务失联、日志失败、提交响应丢失、超过两分钟仍运行及页面刷新；用不同账户查询及以同批次改参数重提 | 预检查后台执行且不写业务单据，确认后按 5,000 行批量写入；查重和历史成本候选查询参数受控，不加载原始 JSON，品牌内复用档案不混入其他单据取价候选。表头、明细、汇总和成功状态同事务，失败全部回滚；覆盖保留原 ID/编号并更新交期和说明。成功后日志失败不误报，档案缺失继续阻止；批次隔离到当前用户，文件及参数变更拒绝复用 ID。前端超过两分钟持续核验，断线和刷新仅查询原批次，采购与经营历程会话标识独立，不自动重提 |
| REG-24 商品档案条码搜索 | 在总览和指定品牌输入货号或原始货号、多货号，含跨品牌同货号、配置品牌、两种条码规则、尺码名称与条码值不同及合码；增加缺规则、缺颜色、无尺码组、空尺码条码和已删除档案。超过 50 条结果后编辑未提交条件再翻页，模拟错误重试、复制失败、关闭与换品牌后响应迟到；核对窄屏和深浅主题 | 完整条码由当前档案货号、所需颜色代码及尺码条码构造，不读取历史库存或改变档案；缺配置显示明确维护提示。不同品牌独立，删除排除，接口无成本及来源 JSON，分页统计展开行且顺序稳定。只在提交后查询，翻页沿用已提交货号，弹窗关闭或变化中止旧请求；复制准确完整条码，失败可手选。主列表条件不因弹窗搜索改变，窄屏可滚动查看完整结果 |

跨网页同步回归 REG-25：同一浏览器同一站点打开两个标签页／窗口，分别验证商品档案、条码搜索、采购单、经营历程、采购／进货明细和仓库库存。另一页成功修改、删除或完成导入后，当前页按已提交条件和页码更新；未提交搜索及编辑草稿不被覆盖，编辑结束后处理积压通知。隐藏页回前台刷新一次，重复通知合并；预检查、查询、失败与运行中任务不通知，后台成功仅通知一次。同页采购单保存继续保持行位置；通知仅含资源及随机标识，存储禁用或通道不可用不影响业务保存。覆盖退出页面后取消待刷新、过期请求不覆盖新查询；跨设备同步不属此场景。

条码搜索导出回归 REG-26：查询超过 50 条、翻至第二页并编辑未提交输入后导出，完整 Excel 仍按已提交品牌和货号包含全部结果，顺序与查询一致。覆盖配置品牌、总览、前导零、超过 15 位纯数字条码、类似公式的品名、尺码名称与尺码条码不同及缺资料记录；核对冻结表头、筛选和列宽。无查询／无结果禁用，无导出权限隐藏且接口拒绝；失败保留结果可重试，导出中不重复提交，关闭取消下载；超出单表行数自动分表，日志异常不误报导出失败。

库存场景 REG-05 中同仓调拨数量同时进入本期入库和本期出库，因此 A 的两项均为 6；如果仅核对仓库净变动，应仍为 0。用例应验证目标实现的两端口径，不只比较期末数字。

商品含尺码导出字段回归 REG-28：准备货号和原始货号不同的商品，覆盖内置／配置品牌、尺码组、无尺码组、历史尺码资料和同原始货号多个商品。按导入日期范围执行“导出记录（含尺码）”，并复验选中／筛选导出。“款式编码”取对应档案货号 `sku`，“商品名”取该货号与颜色名称直接拼接，颜色为空时显示货号；货号含前导零或长数字时保留文本。商品编码、原始货号、尺码展开及其他字段继续沿用各自规则。

商品导入完整错误清单回归 REG-27：采购单、经营历程模板和明细重新导入分别构造至少 62 条商品错误，分散在不同单据、品牌及 Excel 行，包含不存在、已删除、其他品牌、错误颜色／尺码、歧义编码及仅填货号的采购行；模板和采购文件增加空商品编码及带“合计”标识的汇总行。预检查及确认导入均返回全部错误行、编码、品牌、摘要和原因，同一编码重复出现保留各行号，汇总行不误作空商品错误，提示联系商品部且整个批次无业务写入。先通过预检查后删除档案，再确认仍须阻止；取消的单据不阻止其他有效单据，费用类继续豁免。后台失败及页面恢复保留完整清单且不同账户不能读取；模拟失败状态持久化暂时中断后重试，完整明细不得丢失。前端每页 50 条、末页可达、复制全部覆盖所有页并保留前导零，失败可重试；换文件清空旧清单，旧版文本错误仍可读，375px 和深浅主题下清单可横向滚动。

采购单经手人回归 REG-29：使用与单据经手人不同的账户打开并保存采购单，覆盖原值有姓名、空字符串及空值；仅修改摘要、接口省略单据类型或经手人时，单据原经手人保持不变。新增采购单经手人为空且允许填写，编辑时允许手动修改，保存及刷新后使用填写值；采购导入保留文件中的经手人。切换操作账户不替换经手人，操作日志仍记录实际操作账户。复验经营历程新增／编辑仍按当前账户赋值、模板导入仅补齐空经手人的现有规则。

含尺码导出档案归属回归 REG-30：同品牌建立两个供应商、品名、工厂款号及成本不同的商品，将原始货号填为相同值（例如 `240-270`），并使另一商品更新时间更晚；分别选中一个／两个商品导出，覆盖有尺码组及无尺码组的回退行。每行字段来自该款式编码对应档案，不能串用另一商品；另构造一商品准确货号等于另一商品原始货号，准确货号仍优先。确认删除档案排除、品牌隔离及含尺码导出的款式编码／商品名规则保持一致。

采购导入跨档案匹配回归 REG-31：导入窗口不显示品牌选择，预检查和确认导入均不传品牌。两个品牌建立同名供应商，各建有效完整条码；同一文件、同一张采购单包含多个品牌商品时均可导入，匹配结果由明细商品编码决定，与供应商／仓库品牌及旧客户端传入品牌无关。同货号但不同颜色或尺码规则可唯一匹配的商品分别保留档案身份，不能合并；同一完整编码对应多个档案、商品缺失／已删除、条码不符、仅填写货号时列出全部错误行且无业务写入。覆盖明细同样跨档案匹配；供应商名称不完全一致仍阻止，经手人保持文件填写值；经营历程匹配行为不变。

商品销售明细回归 REG-32：隔离库准备批发销售单、批发销售退货单、进货／采购单、已删除销售单、无明细销售单和零／空单价商品行；退货覆盖正数与历史负数数量金额、小数。仅显示未删除的两类销售单据明细，退货按负绝对值展示和扣减合计；单据日期、稳定行号、跨页与越界页的全部合计保持正确。组合品牌多选、客户模糊搜索、仓库多选、日期、货号、品名、颜色和尺码，列表与 Excel 使用已提交条件，筛选草稿不影响导出；客户候选来自已有销售单据，不混用供应商工厂代码。页面入口位于进销存管理，筛选会话与进货／采购明细隔离；返回页面恢复状态，其他标签页修改数据后刷新。`inventory.view` 可查列表、选项和日志，`inventory.export` 控制导出，无权或未登录拒绝，超过 100000 条明确提示缩小范围。复验商品进货明细退货口径及采购明细结果不变。

启动兼容字段锁回归 REG-33：仅在独立 PostgreSQL 测试库构造当前表结构与合成单据；一个连接开启事务并读取 `inventory_details`、`inventory_records`，另一个连接设置短锁超时后重新执行进销存初始化。先用保存点复现已有字段的 `ADD COLUMN IF NOT EXISTS` 仍会锁超时，再确认新版字段检查不发送多余加列／非空约束修改，完整初始化可完成且原数量、单价、金额、条码不变。另构造缺少兼容字段及可空约束的旧表，确认会补齐并保留值，再次检查不重复修改；缺字段且有读取锁时仍报告迁移锁超时，不吞掉异常。补充 SQLite 已有字段跳过检查。测试库限定本机独立端口和临时目录，结束关闭，不启动业务后端、不连接业务库；业务库当前无阻塞不作为已查明历史持锁会话的证据。

## 执行记录模板

以下内容填写到对应开发任务或交付记录，保留记录链接；本文件保存场景及模板，不追加敏感业务执行日志。

| 字段 | 填写要求 |
|---|---|
| 代码／环境 | 项目名称、代码版本、规范版本、隔离环境标识，不写实际连接串 |
| 执行人及时间 | 执行人、日期及时区 |
| 影响范围 | 修改模块、选择的场景 ID、未选场景的必要说明 |
| 输入与步骤 | 合成数据构造规则、采用的模板及请求／页面步骤，足以供另一人复现 |
| 预期及实际 | 各场景的预期、实际、通过／失败／未执行／不适用；失败的原因和影响 |
| 验证命令及限制 | 实际执行命令、通过／失败数量、原有失败、未验证能力；本地验证不表述为线上部署 |
| 处理结果 | 缺陷／开发任务链接、需要的迁移或人工生效方式及复验人 |
