# 赫德业务回归验收清单

版本：1.0

更新日期：2026-11-06

适用说明：[赫德项目规范适配说明](赫德项目规范适配说明.md)，采用[模块开发规则与 UI 规范 v1.3](项目开发规则与UI规范.md)。

本清单包含赫德商品、库存、财务权限及测试入口。独立模块采用[通用回归验收清单](通用回归验收清单.md)并补齐主项目集成场景 GEN-13；涉及既有业务时同时复验本清单受影响场景。下文“规范第 X 节”均指赫德适配说明中的对应章节。

本清单是随仓库提供的长期业务场景入口，不代表下列场景已在当前部署全部通过。修改涉及的模块时选择对应场景复验；独立项目按实际接入范围采用，尚未实现的能力标为“未实现”或“不适用”并说明依据。

## 使用方式

1. 取得目标项目代码，记录代码版本、规范版本、执行人、环境和受影响场景 ID。安装、环境配置及人工启动方式见规范第 2.4 节。
2. 仅在隔离数据库和专用测试账号中执行。构造合成数据，不复制正式密码、用户资料、成本、订单或桌面文件；后台任务和文件来源使用本地测试目录。
3. 按下表准备最小数据、执行操作并对照预期。合成货号、账号和单据可替换，但须保留品牌、状态、空值及边界关系。
4. 在开发任务或交付记录中保存本次使用的合成输入规则、请求步骤或操作步骤及预期，供其他人重新构造；结果分别记为“通过／失败／未执行／不适用”，说明原因。新缺陷补充场景，不把一次运行结果永久写成能力保证。
5. 临时后端脚本、日志、导出及数据库留在忽略目录；不上传 `backend/tests/`。长期复验按本清单执行，不要求其他同事取得本机 `outputs/logs/`。

| REG-03 经手人与重复导入 | 模板一组经手人留空，另一组写入合成姓名；分别走普通／后台导入。用同一任务 ID、文件及参数重复提交；另用新 ID 重复导入相同业务单据 | 空白经手人取当前账户姓名，无姓名回退用户名；已填姓名保留；同任务不重复执行；新 ID 仍执行现有业务冲突检查，不凭新 ID 自动生成重复单据 |

| REG-06 调拨展示及筛选 | 一张 A→B 调拨、一张普通单据仓库为 A、一张普通单据供应商名为 A 但仓库为 C；分别按 A、B 查询并导出混合类型及单一类型结果 | 调拨独立显示出货／入货仓库，筛选匹配两端；不误匹配普通供应商同名；列表、合计、分页和导出同范围；单一单据类型仍按业务生成动态表头 |
| REG-07 多选、跨页与请求先后 | 准备至少两页、不同品牌／年份／季节／品名的数据。编辑条件但不提交，随后多选并查询、换页、全选筛选结果及导出；清空后重查。模拟旧请求晚于新请求返回 | 未提交条件不影响当前结果；同字段多选为任意命中，不同字段同时满足；合计和导出覆盖已提交范围；清空清除不适用勾选；迟到响应不覆盖新结果 |
| REG-08 业务与系统权限 | 准备财务普通账号、无相应业务权限账号及未登录会话；分别通过页面和直接 API 尝试读取／编辑／导出。财务账号另尝试用户管理、定时任务、MCP 令牌及用户管理日志 | 财务可用规范约定的全部业务功能，成本和导出按明确权限；系统管理继续拒绝；无权和未登录不能靠直接请求绕过；不通过增加 `*` 或升级超级管理员取得业务访问 |
| REG-09 详情、会话及错误 | 查询后跳转返回、浏览器刷新、退出并切换账号；列表加载后更新商品再开详情；模拟加载、无数据、请求失败及旧详情响应迟到 | 跳转恢复条件和滚动，刷新恢复默认，账户状态隔离；失败不伪装成空数据／零值；详情不冒充最新。当前商品详情刷新差异见规范第 4.3 节，未改造前如实记录，不忽略失败 |
| REG-10 大文件及后台结果 | 使用合成数据生成足以覆盖多个查询／写入批次的模板；观察整条解析和写入链路的内存与耗时。覆盖上传超限、业务校验失败、网络中断后核验同批次 | 超限按当前上限拒绝；批内失败无部分业务写入；网络中断显示待核验，不自动重传；任务结果可按原批次核对；分批写入不作为内存恒定的证据，不用正式大文件做压力验证 |
| REG-11 新流程状态与并发 | 对新增流程用有权／无权身份请求允许和不允许的状态迁移；同幂等键重复提交及改变请求内容；两个会话基于同一旧版本修改 | 服务端校验权限和前置状态；重复操作不重复生成记录，不同内容明确冲突；第二个旧版本不静默覆盖；状态与业务数据及必要历史同事务；记录操作者、业务／系统时间及必要原因。本场景为新流程验收要求，不宣称中台全部已有 |
| REG-12 并行项目与 UI | 中台与独立项目使用各自端口、数据库、文件目录及隔离会话。检查深浅主题、375／768／1280px、键盘操作、长文本、下拉／弹窗、导入错误提示及复制反馈 | API 指向预期环境，互不覆盖资料或登录态；复用统一主题／组件；动作可达、焦点清楚、无浮层裁切；无匹配／无权／失败分别说明。错误编码只有部分返回时标明已显示数量，不称复制了全量 |

采购单供应商工厂货号筛选回归 REG-49：客户／供应商筛选候选项在供应商名称右侧显示供应商档案的 `factory_code`，名称较长时仍保留货号位置，悬停可查看完整名称及货号；空货号不显示空括号或占位文字。支持供应商名称及工厂货号的模糊匹配，英文忽略大小写，前导零保留；可通过点击或唯一候选回车多选。搜索提交的仍是供应商名称数组，不能把展示货号拼进供应商条件；多个供应商按任一匹配，其他筛选口径保持原规则。只调整采购单管理候选展示与提示文字，经营历程原有客户／供应商选项及搜索保持可用。

商品档案可读表名回归 REG-50：新增 NS、中文品牌及千百度子品牌分别生成可读 `品牌英文或拼音_products`；纯英文、全角字符、数字开头、标点、超长名称按规则规范，长度为索引约束留足空间。同名拼音、大小写及已有表／视图／配置冲突时使用品牌 ID 和必要序号，不覆盖原数据；编辑品牌名称保持表名和品牌代码稳定。旧式和新式表名均能执行商品查询、采购／经营历程匹配、按编码进货／销售明细及仓库库存来源解析，非法标识拒绝。原地迁移保留商品／身份／单据关联 ID、有效／已删除状态、行数、触发器、视图及序列；索引／约束改名后不重复创建。重复执行跳过，目标身份冲突或锁超时整体回滚，第二张表失败时第一张也恢复原状；降级可还原旧式表名。每周检查动态包含配置中的全部有效档案表，MCP 来源仍识别；不覆盖旧报告。隔离 PostgreSQL 验证迁移和新增表，正式库仅在负责人停止后端并授权后迁移、只读核验；由负责人手动启动兼容代码，不改 backend/tests。

明细跨页勾选导出回归 REG-51：采购明细、商品进货明细和商品销售明细分别勾选首页与下一页、返回首页反选；本页全选仅作用于当前页，部分选中显示半选态，其他页选择保留，已选计数正确。翻页、每页条数、日期排序及返回页面保留，三页面和账号隔离；编辑筛选草稿不变，提交查询、清空筛选及切换按货号／编码清空。编码模式同一明细的不同尺码分别选择，兼容原始尺码键、前导零、未分配余量和缺档案提示，不能多导同商品其他尺码；按单据原金额分摊完成后再筛选，所选行金额与全量同一行逐分一致，退货正负号及零数量金额保留。POST 正文传所选标识、查询参数沿用已提交范围；空／非法／重复／越界／10 万行选择和同页与跨页组合正确，超过上限拒绝，空数组不能退成全量。已删除或不再符合条件及消失尺码行返回 409，不能只导仍存在的部分；错误展示并保留选择可重试，导出中禁重复、离开页面或新查询取消旧下载。原全部筛选导出保持可用；前后端分别检查采购／库存导出权限，操作日志说明所选或全部。桌面、375px 和深色合成浏览器验收确认无整页横向溢出、翻页表格与分页位置不变；SQLite 与隔离 PostgreSQL 验证筛选和 100000 个标识绑定，不启停业务后端、不写 backend/tests。

采购单标签条码回归 REG-52：在 80×60mm、640×480 点阵上使用短码、常见货号加颜色尺码、较长字母数字码和前导零数字码；预览与本机打印共用 Code128 编码和几何布局。黑条与白间隔均为整数个窄模块，窄模块至少 2 点，左右各保留至少 10 个窄模块静区，条码居中，不通过横向缩放填满元素。元素边框计入可用宽度；调整模板宽度后重新计算整数模块，不能裁掉开始／结束符。过长编码、过窄区域及无效 Code128 内容在预览明确提示，点击打印时整批拒绝且不向本机服务发送部分任务。浏览器实际 Canvas 位图打包后仍保留编码、条宽与静区，预览切换商品／尺码和模板编辑继续有效；拦截打印 POST 验证 640×480 位图及标签数量，不发送实际打印任务。软件验证不能替代真实标签的打印和扫码复验；不更换编码内容、条码类型或打印机浓度／速度，不启停业务后端。

后台导入有限并发回归 REG-53：默认两个不同账号同时提交采购单／经营历程后台任务，两个解析或预检查均能开始并独立查询结果；第三个返回 429、不创建批次且不执行，已有批次 ID 重试仍返回原结果、异用户不能取得结果。任一任务成功、校验失败、写入回滚、线程异常或提交失败后释放名额，可再次提交；并发等待写入时心跳继续正常更新。两个批次在写入前使用同一进程锁，不占用第二个数据库事务等待前一批次，前一批次失败时锁同样释放；保留原 PostgreSQL 事务锁跨进程保护。使用隔离 PostgreSQL 验证不同摘要同日期编号不重复，同摘要同时新增只成功一批且另一批明确冲突，采购与经营历程写入互斥且单据／明细／批次状态整批提交；预检查仍无业务写入。配置 `INVENTORY_IMPORT_MAX_WORKERS=1` 时保留单任务行为，非法值回默认、数值限制在 1–2；不增加无界任务队列、不启动业务后端、不修改 backend/tests。并发上限不作为大文件内存恒定的证据。

缺失导入批次恢复回归 REG-54：采购单、经营历程在提交响应丢失后查询返回 404，继续保留批次及等待状态，显示“核验并重新预检查”。点击后仅发送恢复核验请求，不上传文件；服务端用相同批次主键登记未接收任务已关闭，确认后才清除当前批次及旧预检查／覆盖选择，保留当前已选文件供重新检查，刷新后丢失的文件需重新选择。关闭登记与迟到提交竞争同一主键：关闭先完成则旧提交拒绝且业务函数不执行，提交先完成则原批次不变并继续返回 queued／running／succeeded／failed。已成功不能改失败，已有失败保留错误，其他账号批次不泄露、不关闭；格式错误 400，无权或未登录继续拒绝。恢复请求超时、接口不存在或服务异常时保留批次和禁止重复提交；离开页面取消核验，迟到响应不清除新页面状态。SQLite 和隔离 PostgreSQL 验证幂等、并发竞态及状态；前端验证刷新恢复、执行中禁用、网络错误、两种导入路径和任务已接收时继续轮询，不改 backend/tests、不启停业务后端。前后端更新后生效，无需结构迁移。
