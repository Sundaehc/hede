# 数据库表目录

更新时间：2026-08-03

本文档依据当前 PostgreSQL `public` schema 的实际元数据、项目表定义及导入/查询代码整理。用于回答“每张表记录什么、应从哪里查询”的问题，不包含连接串、账号密码或共享盘路径。

## 使用说明

- 当前库包含 `67` 张普通表、`6` 张分区父表和 `14` 个视图。
- 下文“记录数”取自 PostgreSQL 统计信息 `n_live_tup`，为估算值；需要精确数量时再执行 `COUNT(*)`。
- 下文“占用”使用 `pg_total_relation_size`，包含表数据、索引和 TOAST 数据；空父表/兼容表通常显示为 `0`。
- 导入型表通常保留 `source_workbook`、`source_sheet`、`source_row_number`、`raw_payload`（以及部分表的 `extra_fields`），用于追溯原始 Excel 行。
- 业务查询优先使用正文标明的视图或当前分区，不应把“0 行的父表”误判为没有历史数据。

| `v_vip_daily_sales` | 统一唯品年度日销分表。 | 唯品日销量跨年份查询。 |
| `v_vip_product_daily_normalized` | 规范化唯品周期指标的起止日期。 | 唯品罗盘、环比、拒退等周期指标查询。 |

## 九、常用查询入口速查

| 业务需求 | 首选数据入口 | 备注 |
| --- | --- | --- |
| 商品基础资料、材质、成本、上市日期 | 品牌商品档案表 + `gj_merged_product_info` + `jst_product_price` | 管家婆资料取最新 `source_date_value`；成本优先使用聚水潭价格表的成本字段。 |
| 货品表当前库存/尺码库存/在途 | `jst_size_stock`、`jst_stock_summary`、`jst_full_stock` | 尺码库存看 `jst_size_stock`；采购在途看 `jst_stock_summary.purchase_in_transit_qty` 或全量库存明细。 |
| 货品表按日期回看 | `v_product_goods_detail_snapshots` | 按 `brand + snapshot_date` 查询。 |
| 货品表历史销量/订单 | `v_product_goods_historical_sales`、`v_product_goods_historical_orders` | 按 `sales_date` / `order_date`、`brand`、货号和渠道筛选。 |
| 唯品日销量 | `v_vip_daily_sales` | 2026 年数据在 `vip_daily_sales_2026`。 |
| 聚水潭日销量和渠道销量 | `v_jst_daily_sales` | 以 `channel` 为渠道归类来源。 |
| 精细表当前经营指标 | `vip_product_daily`、`vip_product_ops`、`jst_monthly_orders`、库存表 | 由精细表接口聚合，不建议人工重复拼接。 |
| 精细表历史按日期查看 | `v_fine_table_snapshot_rows` + `fine_table_snapshot_batches` | 按批次品牌和快照日期定位。 |
| 定时任务执行情况 | `scheduled_task_statuses` | 查 `task_name`、`business_date`、`status`、`message`。 |
| 操作审计 | `operation_logs` | 超级管理员操作仅本人和系统管理员可见，遵从接口权限过滤。 |

## 十、维护注意事项

- `*_2024`、`*_2025`、`*_2026` 为年度分区/分表时，跨年查询优先使用对应 `v_` 视图；直接只查父表可能返回 0 行。
- `fine_table_snapshot_payloads`、`fine_table_snapshot_metrics` 和 `fine_table_snapshot_refs_YYYY` 是一组不可拆开的精细表历史数据；清理快照时必须按批次和引用关系处理。
- `raw_payload` 是数据追溯凭据，不应在常规查询中作为筛选字段；需要排查导入问题时再读取。
- `jst_product_profiles`、`vip_product_detail_daily` 及进销存预留表当前无业务记录，后续启用前应先确认导入任务和唯一键规则。
- 表结构、分区或视图发生变更后，应同步更新本文档和 [database-spec.md](database-spec.md)。
