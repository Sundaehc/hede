# 商品运营中台技术文档

**文档版本**：v1.0  
**更新时间**：2026-07-26  
**适用范围**：赫德商品运营中台当前已实现的商品档案、商品精细表、商品货品表、采购单、进销存与系统管理能力。

> 本文以当前仓库代码、数据库 Schema、批处理脚本和 Windows 任务计划配置为准。规划中的 AI 能力不属于当前系统实现范围，应以对应 PRD 另行立项和设计。

## 1. 系统定位

商品运营中台是面向千百度男鞋、千百度女鞋、烟斗、伊伴四个品牌的内部业务系统。系统将商品档案、Excel 报表、聚水潭库存/日销、唯品日销、订单历史和进销存单据沉淀到 PostgreSQL，并提供统一的查询、编辑、导入导出、快照追溯和权限控制能力。

当前业务边界：

- **商品档案**：四品牌商品主数据维护、Excel 导入导出、图片匹配和图片服务。
- **商品精细表**：商品经营数据查询、筛选、自定义列、导出及按日快照回溯。
- **商品货品表**：货号明细、去颜色款号汇总、缺货风险；组合商品档案、库存、销量、历史订单和人工维护字段。
- **采购单管理**：采购订单、采购需求说明、模板导入导出。
- **进销存管理**：单据、单据明细、进货明细、供应商、仓库、一般客户、会计科目与余额/往来查询。
- **系统管理**：用户、部门、角色权限、登录会话和模块操作日志。

## 2. 总体架构

```text
浏览器
  │
  ▼
Next.js 16 前端（默认 3001）
  │  /api/* rewrite
  ▼
FastAPI 服务（默认 8137）
  │
  ├── PostgreSQL：业务主数据、单据、快照、日销、权限与日志
  ├── Windows 任务计划：按日调用 .cmd / Python 导入和快照脚本
  ├── 局域网共享目录：Excel、聚水潭、唯品、货品表、图片来源
  └── 图片服务：按品牌受控读取共享图片目录后通过 API 返回
```

系统不在 FastAPI 进程内运行 APScheduler 或 Cron。日常数据更新由 Windows Task Scheduler 启动 `backend/scripts/*.cmd`，脚本再调用 Python 模块完成导入、写库和日志记录。

## 5. 前端设计

### 5.1 页面与导航

左侧导航由 `frontend/components/sidebar-nav.tsx` 维护，按权限展示以下模块：

| 导航分组 | 页面 | 权限 |
| --- | --- | --- |
| 商品档案 | 商品信息档案 | `product.view` |
| 商品档案 | 商品精细表 | `fine_table.view` |
| 商品档案 | 商品货品表 | `product.view`，另有部门限制 |
| 采购单管理 | 采购单管理 | `purchase.view` |
| 进销存管理 | 经营历程、商品进货明细、供应商、仓库、一般客户、科目 | `inventory.view` |
| 系统管理 | 用户管理 | `system.admin` |

应用根布局统一注入 `ThemeProvider`、`AuthProvider` 和 `AppShell`。前端通过 `NEXT` rewrite 将 `/api/:path*` 代理到 `BACKEND_URL`，未设置时代理至 `http://127.0.0.1:8137`。

### 5.2 货品表与精细表性能设计

- 货品表默认品牌为千百度男鞋，默认单页 50 条；款号汇总和缺货风险使用独立分页大小。
- 货品表支持完整视图、自定义列、字段旁筛选、排序、日期快照、图片预览、明细抽屉和 CSV 导出。
- 货品表前端维护最多 12 个页面缓存，TTL 为 3 分钟；同请求合并、相邻页预取、视图/品牌悬停预取，避免切换时重复请求。
- 精细表也维护前端分页缓存和相邻页/品牌预取策略。
- 后端货品表使用进程内 LRU 缓存：列表和风险编码缓存 5 分钟，筛选选项缓存 1 分钟。数据编辑、导入或快照回填后应调用缓存清理。

缓存仅用于加速查询，不是数据一致性来源；跨进程部署时应替换为 Redis 等共享缓存，或明确采用单实例服务。

## 7. 身份认证、权限与审计

### 7.1 身份与会话

- 用户、部门、角色、会话分别存储在 `auth_users`、`auth_departments`、`auth_roles`、`auth_sessions`。
- 登录成功后服务端生成随机会话令牌，仅保存其 SHA-256 摘要；浏览器使用 HttpOnly Cookie `hede_session`。
- 会话有效期为 7 天，退出登录会吊销当前会话。
- 权限以角色的逗号分隔权限码保存，超级管理员使用 `*`。

默认部门包括财务部、商品部、运营部、开发部、美工部、客服部。默认角色覆盖商品、精细表、采购、进销存和系统管理权限。

### 7.2 货品表特殊权限

除 `product.view` 外，`/product-goods` 还在后端中间件进行二次拦截：仅 **超级管理员、商品部、开发部** 可访问。前端导航同步隐藏该入口，但后端校验才是最终安全边界。

### 7.3 操作审计

商品、货品表、精细表、进销存、采购、供应商、仓库、科目、一般客户和用户管理的写操作可写入 `operation_logs`。日志包含操作者、角色、模块、动作、对象、变更摘要及变更前后数据。

普通用户查询操作日志时会自动排除超级管理员产生的记录；超级管理员可查看全部记录。日志查询本身仍受对应业务模块的查看权限控制。

### 7.4 安全改进建议

- 当前用户密码哈希为 MD5，仅适用于受控内网的历史实现；应迁移到 Argon2 或 bcrypt，并支持登录时渐进升级。
- 当前登录 Cookie 的 `secure=False`，若前端切换到 HTTPS，必须改为 `secure=True`，并配置可信反向代理。
- `.env`、数据库口令和网络共享访问凭据不得提交到 Git；生产环境应使用受控密钥管理和最小权限账户。

| 颜色条码 | `color_barcodes` | 颜色与条码辅助映射。 |

### 8.2 采购与进销存

| 表 | 作用 |
| --- | --- |
| `inventory_records` | 单据主表，保存日期、摘要、往来单位、仓库、单据类型、总数量和金额。 |
| `inventory_details` | 单据明细，外键关联主单据，包含商品编码、名称、颜色规格、数量、单价、金额和尺码数量 JSON。 |

明细行增删改后，由 Repository 汇总数量和金额回写主单据。单据删除采用回收站逻辑，恢复与批量删除使用独立接口。

### 8.3 日销、库存与分析数据

| 数据类别 | 表/表模式 | 主要用途 |
| --- | --- | --- |
| 聚水潭日销 | `jst_daily_sales_YYYY` | 按年份保存渠道、货号、款号、颜色、条码、销售量/金额、退货等。 |
| 唯品日销 | `vip_daily_sales_YYYY` | 按年份保存唯品商品、尺码、货号、销量、销售额和在售库存。 |
| 尺码库存 | `jst_size_stock`、`jst_size_stock_snapshots` | 当前尺码库存与按日快照。 |
| 库存汇总 | `jst_stock_summary`、`jst_stock_summary_snapshots` | 在途、占用、下架等库存汇总与按日快照。 |
| 全量库存 | `jst_full_stock` | 从聚水潭库存全量表导入，提供可用、在仓、进货仓、在途、尺码、近销和周转等字段。 |
| 历史销量 | `product_goods_historical_sales_2024`、`product_goods_historical_sales_2025` | 由固定历史工作簿回填的年度销量数据。 |
| 历史订单 | `product_goods_historical_orders_YYYY` | 从 2022 年开始按年存放订单日期、货号、渠道和数量。 |
| 店铺渠道映射 | `product_goods_shop_channel_mappings` | 按品牌将店铺名称映射为唯品、天猫、得物、拼多多、京东、商品卡、直播、达播清仓等渠道。 |
| 货品期间销量 | `product_goods_sales_periods` | 从商品明细工作簿提取的日/周/月等期间销量。 |

年度及快照数据按年分表，是为了避免单表持续膨胀、降低索引体积，并保持按业务日期的查询和维护边界清晰。

### 8.4 快照与人工覆盖

| 表/表模式 | 说明 |
| --- | --- |
| `fine_table_snapshot_batches`、`fine_table_snapshot_rows_YYYY` | 精细表按品牌和日期保存批次与行 JSON，可回看历史日期。 |
| `product_goods_detail_snapshot_batches`、`product_goods_detail_snapshots_YYYY` | 货品表按品牌、日期、货号保存完整计算结果或导入明细。 |
| `product_goods_overrides` | 货品表人工维护字段：所属平台、四级分类、商品角色、类型、抖音爆款、清仓、备注及扩展 JSON。 |
| `scheduled_task_statuses` | 记录部分具备状态上报能力的日任务，按任务名和业务日期唯一。 |
| `operation_logs` | 用户操作审计。 |

## 9. 商品货品表数据链路

### 9.1 数据优先级

货品表不是单一物理表，而是在查询时按品牌聚合。数据优先级如下：

1. **商品档案**：货号、款号、颜色、图片、成本、年份、季节、工厂货号、供应商等基础字段。
2. **人工覆盖**：`product_goods_overrides` 中的所属平台、分类、角色、类型、抖音爆款、清仓、备注；补单相关人工字段存放在扩展 JSON。
3. **库存数据**：优先使用 `jst_full_stock` 获取在仓、进货仓、在途、可用、尺码和周转相关数据；历史日期使用尺码库存/库存汇总快照及货品表明细快照。
4. **实时/当年销量**：合并 `jst_daily_sales_YYYY` 与 `vip_daily_sales_YYYY`。聚水潭行按 `channel` 和店铺渠道映射归类；唯品日销固定归入唯品渠道。
5. **历史销量和订单**：使用按年历史销量表、2022 年起订单表和期间销量表补足年度、月度、订单等指标。
6. **日期回溯**：存在 `product_goods_detail_snapshots_YYYY` 时优先读取该快照计算结果，确保历史日期不被当前档案或当前库存覆盖。

若来源未提供某字段、货号无法匹配、日期尚未快照，页面应显示为空，不能用零值伪装为真实业务数据。

### 9.2 主要指标口径

- **日/周/月销量**：以业务查询日为基准，日为单日、周为最近 7 个自然日窗口、月为当前自然月；渠道拆分来自聚水潭 `channel`/店铺映射与唯品日销。
- **年度销量**：优先按年聚合当年日销，结合 2024/2025 固定历史销量回填数据。
- **在仓库存+进货仓**：基于 `jst_full_stock` 的实际库存与进货仓库存字段按货号/尺码汇总。
- **在途库存**：基于采购在途、调拨在途、退货在途等来源字段，货品表可按尺码展示时以全量库存尺码行归集。
- **库存合计/缺货库存/补单后库存**：由尺码库存、在途、人工补单明细及页面计算逻辑组合；补单数据尚未对接自动采购来源时保持人工维护。
- **工厂代码**：根据供应商名称关联 `suppliers.factory_code`；供应商未建档或名称不一致时为空。

### 9.3 货品表接口与可维护字段

- `GET /product-goods`：支持品牌、视图、关键词、分页、字段筛选和历史日期。
- `GET /product-goods/filter-options`：返回可选筛选值，前端用于表头筛选。
- `PATCH /product-goods/{product_id}`：更新人工字段并清理服务端缓存。
- 货号明细、款号汇总、缺货风险是不同的查询视图；款号汇总按去除颜色后的款号归集库存和销量。

## 10. 外部数据、导入与图片

### 10.1 外部来源

配置文件 `backend/.env` 提供数据库、前端来源、商品 Excel 根目录、各品牌图片根目录、聚水潭库存、唯品、价格、商品资料、精细表导出、售后、日销和货品表共享目录等路径。代码中提供默认局域网路径，但部署应通过环境变量覆盖，且不得在文档或代码中写入账号口令。

主要导入来源：

- 商品档案工作簿和聚水潭商品资料表。
- 聚水潭库存、商品库存、采购差异、全量库存和日销售报表。
- 唯品日销售报表及唯品运营数据。
- 四品牌商品运营货品表中的商品明细、订单、历史销量和渠道映射工作表。
- 管家婆合并商品信息、供应商资料、售后退货和精细表来源。

### 10.2 幂等与追溯

- 商品档案以品牌内 `sku` 唯一，导入前保留最后出现的重复货号。
- 日销年表使用业务日期与来源业务键唯一，重复导入通过 upsert/替换策略避免重复累计。
- 历史销量、历史订单、期间销量和快照以工作簿、Sheet、行号或品牌/日期/货号唯一，支持按来源重跑。
- 每条导入记录尽可能保存来源工作簿、Sheet、行号和原始 payload，便于问题追溯。

### 10.3 图片服务

图片不复制进数据库。商品档案保存相对图片路径，图片接口在配置的品牌共享目录中进行受控查找，并返回 `/api/images/serve/{brand}/{path}`。进销存明细支持根据商品编码做跨品牌图片匹配。前端点击缩略图可打开原图预览。

图片目录属于外部依赖：共享路径不可用、权限不足或相对路径失效时，商品图片将不可访问，但不会影响商品主数据查询。

## 11. 定时任务与数据刷新

### 11.1 调度方式

已核对的任务使用 Windows Task Scheduler，调用 `backend/scripts/*.cmd`。`.cmd` 统一在 `backend/logs/` 写入开始时间、结束时间和进程退出码，并使用固定 Python 解释器执行模块。

当前服务器已配置的关键日任务（以 2026-07-26 查询结果为准）：

| 时间 | 任务 | 脚本/结果 |
| --- | --- | --- |
| 00:00 | `Hede Fine Table Snapshot Daily` | 创建前一日精细表快照。 |
| 00:00 | `HedeImportProductGoodsDetailSnapshotsDaily` | 创建前一日货品表计算快照。 |
| 02:00 | `HedeBackfillProductGoodsDetailSnapshots` | 回填货品表明细快照。 |
| 07:40 | `HedeImportJstFullStock` | 全量导入聚水潭库存至 `jst_full_stock`。 |
| 08:00 | `HedeImportProductsDaily` | 同步商品档案。 |
| 08:00 | `HedeImportPriceDaily` | 导入/更新价格历史。 |
| 08:20 | `HedeImportMonthlyOrder` | 导入月度订单数据。 |
| 08:35 | `HedeImportAftersaleReturnsDaily` | 导入售后退货数据。 |
| 10:00 | `HedeImportJstDaily` | 导入聚水潭尺码库存、库存汇总及采购差异。 |
| 10:20 | `HedeImportDailySalesReports` | 从聚水潭日销售报表和唯品日销售报表写入年度日销表。 |
| 10:25 | `HedeImportProductGoodsOrdersDaily` | 读取最新货品表订单数据并更新年度历史订单表。 |
| 11:20 | `Hede Fine Table Export Daily` | 导出精细表日文件并执行相关快照流程。 |

`HedeImportJstDaily` 与 `HedeImportDailySalesReports` 职责不同：前者是库存/采购差异导入，后者才负责写入 `jst_daily_sales_YYYY` 和 `vip_daily_sales_YYYY` 日销表。排查“销量为空”时，应优先检查 10:20 日销任务、共享报表日期、货号/尺码匹配和渠道映射。

### 11.2 任务状态与排障

- 支持状态上报的任务把状态写入 `scheduled_task_statuses`，可按任务名和业务日期判断成功、失败或未执行。
- 所有包装脚本写入 `backend/logs/*.log`；应先查看最后一次的 `errorlevel` 和 Python Traceback。
- 任务当前为交互式 `Administrator` 任务，且大多配置为使用交流电时启动。服务器未登录、睡眠、断网、共享目录不可达或 Python 路径变更都可能导致漏跑。
- 日销重复唯一键应通过导入 Repository 的业务键 upsert 解决，不能以“重复无影响”为由忽略失败退出码；失败会使当日数据不完整。

建议每个任务统一写入状态表、增加失败告警，并迁移为可在用户未登录时运行的服务账户任务。

## 14. 已知技术边界与演进建议

| 优先级 | 事项 | 建议 |
| --- | --- | --- |
| P0 | 密码哈希与 HTTPS Cookie | 迁移至 Argon2/bcrypt；启用 HTTPS 后设置 Secure Cookie。 |
| P0 | 日任务可靠性 | 使用非交互式服务账户，统一状态上报、失败重试和告警。 |
| P0 | 数据质量 | 对报表日期、货号、尺码、渠道映射、重复键和导入行数设置校验阈值。 |
| P1 | 缓存共享 | 多实例部署前将进程内缓存替换为 Redis，增加显式失效事件。 |
| P1 | 外部文件依赖 | 将共享目录可达性和文件更新时间纳入任务前置检查。 |
| P1 | 大表治理 | 继续按年分表，建立归档策略，定期执行索引维护和慢查询分析。 |
| P2 | 文档自动化 | 在 CI 中校验迁移、Schema、接口契约和任务清单的一致性。 |
| P2 | AI 能力接入 | 在数据质量、权限脱敏、指标口径和审计闭环稳定后，再接入预测、异常归因和智能问答。 |
