# 查询性能优化

## 范围

本次不删除业务数据、不调整全局内存、不升级全部历史 Alembic 迁移。

- 移除模型中与唯一约束完全重复的普通索引。保留主键、唯一约束、外键索引及不能确认冗余的索引。
- 库存历史日期使用递归索引查找逐个取不同日期，避免扫描上千万条明细。无需新建日期目录表，避免目录与明细不一致。SQLite 保留 DISTINCT。
- 精细表历史快照的非数字文本筛选下推到 JSONB 查询，数据库处理筛选、总数和分页。数字、百分比、实时成本、平台、计算字段仍使用原算法，保留已有相等判断和实时字段语义。
- 最新价格索引使用与查询相同的 `DESC NULLS LAST`，保留空日期排在最后的语义。
- 当年聚水潭、唯品日销增加 `(style_code, sales_date)` 索引，保留原有商品编码前缀索引。
- 为当年聚水潭日销、价格、新结构快照表调整表级自动清理与统计阈值，对聚水潭日销执行普通 `VACUUM (ANALYZE)`，不使用 VACUUM FULL。

## 执行

在 backend 目录预览：

```powershell
uv run python -m scripts.optimize_query_performance --drop-redundant
```

确认后执行：

```powershell
uv run python -m scripts.optimize_query_performance --execute --drop-redundant
```

- 默认仅预览，计划和回滚 SQL 输出到 outputs 下的 JSON。
- 索引创建和删除使用 CONCURRENTLY，每个动作独立提交，锁等待限制为 5 秒。
- 新价格索引成功建立后才允许移除旧排序索引。
- 重复索引只处理明确名称集合，执行时校验有效唯一索引的列、操作符类、排序、谓词及表达式完全相同，不以零使用次数为删除依据。
- 同名索引无效或定义不符时停止，不自动删除未知索引。失败的并发建索引需要人工确认后清理。
- 操作前保存全部计划及回滚定义，每完成一个动作更新报告，失败立即停止。成功动作不会自动回滚。
- 可重跑，不重复创建定义一致的索引，不修改 Alembic 版本。
- 建索引会使用额外磁盘并产生 I/O，建议低峰执行。

## 生效与回滚

数据库索引和表级参数立即生效；日期查询和筛选下推需要重启后端才能被现有进程使用。应核对历史日期列表、筛选总数、分页结果、价格空值及最新价格。

使用对应报告 completed 动作的 rollback SQL，按动作逆序回滚。VACUUM (ANALYZE) 无须回滚。价格回滚先恢复原索引再移除新索引，模型定义应同步恢复，避免启动重新创建已移除的重复索引。
