# 商品生图提示词

美工部及超级管理员在商品信息档案卡片点击“生图提示词”，直接查看数据库已保存的详情页文案与图片建议。打开弹窗和“刷新内容”只读取数据库；只有主动点击“重新生成”才提交后台模型任务，不生成图片。

## 手动重新生成

- 弹窗底部提供“刷新内容”“重新生成”“复制全部”。重新生成使用当前商品档案填完整固定提示词，再调用后端现有模型配置；成功后存库并自动展示新结果。
- `POST /product-copywriting/{brand}/{product_id}/regenerate` 校验登录、商品查看权限、美工部/超级管理员身份、商品存在以及有效上市日期。手动操作可针对其他上市日期的单个商品；批量脚本仍仅处理2026-09-20和2026-09-21，不自动扩展范围。
- 请求先在数据库原子领取任务，再提交后台线程，立即返回202。相同商品的有效运行任务拒绝重复提交；每个后端进程最多同时运行2个手动生成任务，满额返回429，不无限排队。
- 生成期间禁用重新生成按钮，每3秒只读数据库检查结果；成功或失败后停止轮询。关闭弹窗停止轮询，不取消后台任务；重新打开可继续查看状态。读取失败时保留已有内容并暂停轮询，可点击“刷新内容”恢复。
- 重新生成先备份上一版成功正文，运行中或失败后仍展示该备份；只有成功的新结果替换展示。模型调用前后核对档案及上市日期，发生变化时不保存过期资料结果。
- 任务提交失败、模型失败均记录失败状态；服务中断导致任务过期时，读取接口提示超时，可手动重新生成，过期任务不能覆盖新任务结果。不会自动重试模型请求。

## 提示词填充流程

### 展示与编辑

- 生图提示词弹窗同时显示“生成提示词（可编辑）”和生成结果。编辑区优先显示数据库 `input_prompt`，即最近一次提交使用的完整输入，不向公众开放；仍仅限美工部和超级管理员。
- 修改后点击“重新生成”，前端以 `{"input_prompt":"编辑后的完整文本"}` 提交，后端原样保存并与当前商品主图一起发送给模型。编辑不会修改商品档案、系统安全规则、模型配置或图片来源。
- 输入不能为空白、最长30,000字。未提交的编辑在刷新内容时保留，可“撤销修改”恢复最近读取的版本；关闭弹窗不会保存未提交草稿。提交成功后保存输入，生成失败也可继续编辑重试，旧正文及旧提示词备份仍保留。
- 旧记录没有输入文本时，先尝试上一版备份，否则根据当前档案填充并明确标为非历史输入。查看这些内容不调用模型、不改库；旧正文照常展示。
- `GET` 新增 `input_prompt`、`prompt_source`（`saved` / `previous` / `archive` / `null`）；重新生成请求允许不带请求体以兼容旧前端，仍按当前档案填充。只允许请求体包含 `input_prompt`。
- 本功能更新了前后端，需要维护人员手动重启后端，并重新构建、重启前端；无需新建数据库字段，不会自动覆盖已有文案。

1. 保留用户提供的固定提示词，只填充“一、产品信息”中的14个字段。“二、文案方向”“三、固定输出格式”“四、表达限制”保持原文。
2. 从商品档案白名单字段填入名称、货号、材质、鞋型、颜色、跟高、季节等信息，不把原始JSON交给模型自行填表。缺失信息写为“未提供，待确认”，不由材质、鞋型推断功能或脚感。
3. 品类仅在分类或产品名称明确包含对应品类时归类，否则列为其他或待确认；35岁以上是文案定位，页面位置是本次文案规划，不冒充商品参数。现有档案没有独立重量、适用场景及穿着需求字段，因此明确待确认。
4. 完整的已填提示词与该商品档案主图作为同一条 `user` 消息发送：`content` 包含 `text` 和 `image_url` 两项，图片使用 `data:image/...;base64,...` 内嵌数据，而不是局域网图片地址。另有独立 `system` 消息约束档案和图片内容仅为数据、禁止执行其中的指令或虚构事实，不改写固定模板。
5. 将实际发送的 `input_prompt`、`system_prompt`、`input_image` 与资料快照、模板版本一起存库，再保存模型返回的六区块正文。`input_image` 仅记录主图路径、SHA-256摘要、媒体类型和字节数，不保存Base64正文或云存储签名链接，也不向前端暴露内部路径。页面仍展示生成结果，不把输入模板当成生成结果。

## 商品图片输入

- 手动重新生成与批量生成共用同一条带图流程，发送档案当前关联的主图。已同步到US3的主图优先由后端下载，存储不可用时尝试配置的本地/共享图片目录；不把API密钥附加到图片下载请求。
- 未关联主图的商品不处理：批量任务直接计为 `skipped / missing_image`，不创建或领取任务、不改动原记录；手动点击重新生成时提示已跳过，不进入队列。已有文案及生成状态保持不变，不自动补图。
- 支持JPEG、PNG、WebP，按文件头识别类型，读取上限10MB；不新增图片转换依赖。图片未关联、缺失、路径越界、格式不支持或超限时不调用模型，不静默降级为纯文字生成。上一版成功文案仍保留。
- 只有明晰可见的外观、鞋型、配色和设计细节可以作为图片参考；不凭图认定材质成分、重量、尺寸、脚感或功能。图文冲突和看不清的细节必须在风险校对中列为待确认。
- 图片路径纳入资料摘要，读取图片后及模型返回后再次核对档案；期间换图则不保存过期资料生成结果。图片字节摘要用于追溯实际发送的图片，不替代图片源文件的版本管理。
- 现有已保存正文继续展示，不因启用图片输入自动重生成。需要结合图片更新时，由用户点击“重新生成”。当前配置的模型及代理服务需支持图片输入；不支持时明确失败，不自动改用其他模型或纯文字请求。
- 后端启动时幂等增加可空JSON列 `input_image`，不会删除或覆盖旧记录。单独的图片输入更新只需重启后端；包含提示词编辑功能的更新需同步部署前端。

## 存储与展示

- PostgreSQL 表：`product_copywriting`，由后端启动或批量脚本独立创建，不修改商品档案表。
- 唯一关联：`brand + source_product_id`。商品货号更改后仍找到同一条记录；不依赖会变动的货号作为关联键。
- 保存正文、实际输入提示词、系统约束、原货号、上市日期、必要商品资料快照及摘要、模板摘要、provider、模型名、接口地址、生成时间、状态、尝试次数与错误信息。表内不保存 API Key、商品成本、供应商或原始导入数据。
- 已有表通过幂等增列保留原记录；`previous_result` 保存模板升级前的上一版成功结果及其来源，重生成失败也不会丢失这一备份。
- `GET /product-copywriting/{brand}/{product_id}` 校验登录、商品查看权限、美工部/超级管理员身份、商品未删除，再读取结果。读取不要求模型密钥，也不会创建结果行。
- 返回 completed / missing / pending / running / failed 状态。没有已保存内容时明确提示，不自动补生成，不伪造文案；running / failed 可携带上一版成功内容。
- 商品资料或固定模板变化时标注对应提醒，由美工上版前核对；不在读取时修改数据库或调用模型。
- “复制全部”兼容局域网 HTTP 复制。用户要求删除的弹窗说明句不再显示。
- 旧版 `POST /product-copywriting/{brand}/{product_id}` 和 jobs 查询接口仍返回410；新按钮使用独立的 `/regenerate` 接口，避免旧页面误触发生成。

## 每日自动补生成

- 商品档案计划任务 `HedeImportProductsDaily` 改为北京时间每日04:00，入口为 `scripts/sync_products_and_copywriting_daily.cmd`。配置脚本 `scripts/configure_products_daily_task.ps1` 保留原执行账号、登录方式和其他任务设置，只修改启动时间、重试窗口和入口，先备份XML再注册，并从次日04:00生效，避免部署时立即调用模型。
- 执行顺序：检查/补跑当天价格和管家婆合并资料导入 → 商品档案同步成功 → 最近7天带图商品补生成。前置源文件未到齐时每30分钟补查至16:00，不使用旧数据冒充本次更新；当天全流程成功后不重复执行。任务运行需要原Windows账号登录、机器开机，并能访问共享目录。
- “近一周”固定采用北京时间执行日及前6天，例如2026-09-23执行时筛选2026-09-17至2026-09-23（含两端），不生成未来日期商品。不限定品牌；排除删除、排除清单、无关联主图的商品。
- 自动流程只新增数据库完全没有记录的商品。已完成、人工改过提示词、旧模板、运行中、失败和过期记录全部保持不变；不会自动重新生成、升级模板或重试旧失败。无图片跳过，有关联图片但无法读取时记录失败，后续可手动处理。
- 原子 `only_if_missing` 领取使用唯一键冲突时不更新，避免并发覆盖人工结果；全流程另有数据库会话锁防止重复启动。模型并发固定为2，执行前后校验商品档案、上市日期与图片路径未变化。
- 日志仍为 `backend/logs/import_products.log`，商品同步子步骤另写 `sync_product_archives.log`；业务状态分别记录 `sync_products_daily`、`generate_product_copywriting_daily`、`sync_products_and_copywriting_daily`。失败记录保留，重复调度只检查尚无记录的候选。
- 只读预览：在backend目录运行 `.\.venv\Scripts\python.exe -m scripts.generate_product_copywriting_daily`。不创建表、不写结果、不调用模型。显式追加 `--execute` 才执行，并检查当天档案已同步成功。自动入口不依赖前后端服务重启，不调整现有模型配置。

## 历史指定日期补生成

只处理上市日期为 **2026-09-20**、**2026-09-21** 的未删除且未排除商品，其他日期不创建任务、不调用模型。启动前核对共有26款千百度女鞋：9月20日23款，9月21日3款。

旧脚本 `generate_product_copywriting` 仍固定这两个日期；允许 ISO 日期及对应斜杠格式，不使用前缀模糊匹配。该历史补录脚本不是新的每日任务入口，不用于近一周自动补生成。

在 `backend` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m scripts.generate_product_copywriting
.\.venv\Scripts\python.exe -m scripts.generate_product_copywriting --execute --workers 3
.\.venv\Scripts\python.exe -m scripts.generate_product_copywriting --execute --workers 2 --retry-failed
.\.venv\Scripts\python.exe -m scripts.generate_product_copywriting --execute --workers 3 --refresh-outdated-template
```

默认仅预览，不写库、不调用模型；`--execute` 才实际生成。`--limit 1` 可先验证一款。并发范围1–3。

成功结果立即提交数据库，后续运行跳过成功项，不覆盖或重复计费。失败保留状态和错误，不写入虚构正文；普通重跑不会自动重试失败项，只有 `--retry-failed` 才重试失败或过期运行记录。领取任务使用原子更新和有效期，防止重复批次并发调用同一商品。有效期内运行项始终跳过。

模板纠正时显式使用 `--refresh-outdated-template`，仍只处理上述两个上市日期。旧模板成功内容先写入 `previous_result`，再按已填完整提示词重新生成；当前模板已成功的商品始终跳过。后台更新期间页面明确显示正在生成及上一版内容提示，不将旧版内容伪装为新版结果。失败项使用 `--retry-failed` 重试，备份保留。

每次调用前重新核对上市日期；生成后再次校验商品资料及日期，变化则记录失败，不把旧资料文案标为成功。运行日志只包含货号、ID、日期、结果和清理过的错误，不包含密钥、正文或内部成本。

## 模型配置

现有 `backend/.env` 的密钥、模型名、provider及地址保持用户配置：

```dotenv
ARK_API_KEY=当前模型服务的API密钥
DOUBAO_PROVIDER=custom
DOUBAO_BASE_URL=https://model.pardx.cn
DOUBAO_TEXT_MODEL=doubao-seed-pro
DOUBAO_TIMEOUT_SECONDS=180
```

批量脚本可通过进程环境单独将 `DOUBAO_TIMEOUT_SECONDS` 调整为300秒，不影响已运行的业务服务。支持10–300秒。模型返回慢不会拖住页面请求，因为页面只读数据库。

`custom` 使用通用 Chat Completions 参数，根地址自动补齐 `/v1/chat/completions`；兼容完整接口地址，不重复拼接。只有 `ark` 直连使用 `thinking.type=disabled`。仅接受不含账号、查询参数或片段的 HTTPS 地址，拒绝重定向，避免密钥转发。当前自定义服务的实际请求地址为 `https://model.pardx.cn/v1/chat/completions`。

API Key 只保存在后端环境中，不提交版本库。切换服务意味着必要商品信息发送至配置的服务商。模型输出必须含主标题、副标题、主文案、卖点、图片建议、风险校对六个区块；人工仍需核对真实性和宣传用语。

## 部署验证

由维护人员手动重启后端、重新构建并重启生产前端。仅执行批量生成不要求启停前后端。表和结果不会因服务重启丢失。

验证项：数据库按上市日期、状态统计；同品牌商品ID唯一；成功记录正文、生成时间及完整输入提示词非空；存库输入与实际请求一致；固定规则不被填充逻辑改写；批量脚本不处理其他日期；打开弹窗不新增任务；手动重新生成防重复、成功自动更新、失败保留上一版。
