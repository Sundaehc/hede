# 智能查询数据库字段字典

## 1. 文档用途

本文档用于智能查询生成只读 SQL 时理解表用途、字段含义、关联方式和统计口径。字段说明的机器可读版本维护在 `backend/domain/ai_query_field_catalog.py`，智能查询会把与用户问题相关的表、字段类型和中文解释一并发送给 AI。

本文档只描述允许进入智能查询的业务表和标准化视图。`auth_*`、`operation_logs`、`ai_query_history`、PostgreSQL 系统表、手工年度分表和底层快照载荷表不向 AI 任意 SQL 开放。

### 2.2 通用追溯字段

以下字段在多张导入表中重复出现，含义相同：

| 字段 | 含义 | 查询注意事项 |
| --- | --- | --- |
| `id` | 数据库行主键 | 不等同于货号、订单号或单据编号；年度分表合并后可能不能单独作为业务去重键。 |
| `source_workbook` | 来源 Excel 工作簿名称或路径 | 用于追溯和来源级去重。 |
| `source_sheet` | 来源工作表名称 | 用于追溯和来源级去重。 |
| `source_row_number` | 来源工作表行号 | 与工作簿、工作表组合后可标识来源行。 |
| `raw_payload` | 来源原始行 JSON | 仅用于排查导入问题，不作为常规查询结果返回。 |
| `extra_fields` | 未结构化扩展字段 JSON | 使用前必须确认具体 JSON 键，不能猜测键名。 |
| `created_at` | 数据库记录创建时间 | 不是销售、库存或单据业务日期。 |
| `updated_at` | 数据库记录最后修改时间 | 不是业务日期，可用于查询最近维护时间。 |
| `deleted_at` | 逻辑删除时间 | 商品档案和单据查询必须过滤 `deleted_at IS NULL`。 |
| `source_date` | 来源文件日期文本 | 优先使用对应规范日期字段筛选。 |
| `source_date_value` | 规范化来源日期 | 用于选择同一来源的最新数据。 |
| `business_date` | 规范化业务日期 | 标准化视图中优先用于日期筛选、分组和排序。 |
| `date_value` | 原日期文本解析出的日期 | 经营历程中表示规范单据日期。 |

### 2.3 编码匹配

| 编码字段 | 含义与匹配规则 |
| --- | --- |
| 商品档案 `sku` | 当前基础货号，商品档案内使用精确匹配。 |
| 商品档案 `original_sku` | 原始货号或款号，用于款号汇总。 |
| 销量/库存 `product_code` | 通常是基础货号后拼颜色、颜色代码或尺码，关联商品档案时按前缀匹配；多个货号同时命中时保留最长 `sku`。 |
| 唯品 `goods_code` | 唯品商品编码，关联基础货号时同样使用前缀匹配。 |
| 历史订单 `original_sku` | 来源订单商品编码，关联档案时使用最长基础货号前缀命中。 |
| `style_code` | 来源款式编码或款号，粒度可能因来源不同而变化，不能默认等同于商品档案 `sku`。 |

## 5. 库存

### 5.1 当前全量库存 `jst_full_stock`

当前库存查询必须先限定 `sync_date = MAX(sync_date)`。

| 字段 | 中文含义 | 计算用途 |
| --- | --- | --- |
| `sync_date` | 库存同步日期 | 当前库存日期。 |
| `product_code` | 库存商品编码 | 通常带颜色或尺码后缀。 |
| `style_code` | 款式编码 | 来源款式。 |
| `color_spec` | 颜色规格 | 解析颜色和尺码。 |
| `color` | 颜色 | 解析后的颜色。 |
| `size` | 尺码 | 尺码库存维度。 |
| `actual_stock_qty` | 实际库存 | 在仓库存组成。 |
| `purchase_warehouse_stock_qty` | 进货仓库存 | 在仓库存组成。 |
| `purchase_in_transit_qty` | 采购在途 | 在途库存组成。 |
| `transfer_in_transit_qty` | 调拨在途 | 在途库存组成。 |
| `return_in_transit_qty` | 销退在途 | 在途库存组成。 |
| `available_qty` | 可用库存 | 小于 0 时绝对值为缺货库存。 |
| `order_occupy_qty` | 订单占用 | 占用库存。 |
| `stock_sale_days` | 库存销售天数 | 周转指标。 |
| `suggested_purchase_qty` | 建议采购量 | 聚水潭建议值。 |
| `safety_stock_min_qty` | 安全库存下限 | 安全库存配置。 |
| `safety_stock_max_qty` | 安全库存上限 | 安全库存配置。 |
| `warehouse_pending_qty` | 仓库待处理数量 | 状态库存。 |
| `return_warehouse_stock_qty` | 退货仓库存 | 状态库存。 |
| `exception_warehouse_qty` | 异常仓库存 | 状态库存。 |
| `off_shelf_warehouse_qty` | 下架仓库存 | 状态库存。 |
| `worn_warehouse_qty` | 残次/穿着仓库存 | 状态库存。 |
| `live_warehouse_qty` | 直播仓库存 | 状态库存。 |
| `processing_warehouse_qty` | 加工仓库存 | 状态库存。 |
| `temporary_location_qty` | 临时库位库存 | 状态库存。 |
| `yesterday_sales_qty` | 来源昨日销量 | 库存文件自带指标，不等同于统一日销查询结果。 |
| `sales_7d_qty` | 来源近 7 天销量 | 库存文件自带指标。 |
| `sales_15d_qty` | 来源近 15 天销量 | 库存文件自带指标。 |
| `warehouse_name` | 来源仓库名称 | 仓库维度。 |

标准公式：

- 在仓库存 = `COALESCE(actual_stock_qty, 0) + COALESCE(purchase_warehouse_stock_qty, 0)`
- 在途库存 = `COALESCE(purchase_in_transit_qty, 0) + COALESCE(transfer_in_transit_qty, 0) + COALESCE(return_in_transit_qty, 0)`
- 整体库存 = 在仓库存 + 在途库存
- 缺货库存 = `ABS(available_qty)`，仅统计 `available_qty < 0` 的记录

| 表 | 字段 | 中文含义 |

## 13. 防止数据错误的强制规则

1. 聚水潭销量默认使用 `net_sales_quantity`；`sales_quantity` 是毛销量，`return_quantity` 是退货量。
2. 唯品销量使用 `v_vip_daily_sales.sales_quantity`。
3. 合并聚水潭和唯品时，唯品日销优先；仅在同一基础货号、同一日期已有唯品记录时排除聚水潭中映射为唯品的重复记录。
4. 历史销量与逐日销量必须按不重叠日期或年份 `UNION ALL`，不能直接重复相加。
5. `product_goods_sales_periods` 是预计算结果，不能再与对应逐日销量相加。
6. 当前库存与历史库存快照不能相加；比较时分别返回日期和指标。
7. 断码 SKU 当前没有可靠自动来源，不能把库存为 0 直接认定为断码。
8. 空值表示暂无可靠数据，不能默认改为 0；库存组成公式中的数值列可以在加法前使用 `COALESCE(字段, 0)`。
9. 商品档案 `year` 是 `26年春季款` 一类展示标签；`season_category` 是春夏、春秋、秋冬等分类，两者不能混用。
10. 查询当前数据时，日期必须取对应事实表的最大业务日期，不能假设数据库已经更新到自然日今天或昨天。
11. JSON 字段只允许查询已确认存在的键；智能查询不能依据页面中文名自行猜测 JSON 路径。
12. 复杂分析先建立按品牌、日期、货号缩小后的商品范围，各事实表内部先聚合，再关联聚合结果；禁止直接关联两个完整大事实表。

## 14. 维护方式

新增表、删除字段、修改指标口径或调整数据源时，应同步更新：

1. `backend/domain/ai_query_field_catalog.py`：智能查询实际使用的机器目录。
2. 本文档：面向开发和业务人员的数据字典。
3. `backend/domain/ai_query_semantics.py`：需要强制校验的业务口径。
4. 对应测试：确保字段解释、权限裁剪和问题级表裁剪仍然有效。
